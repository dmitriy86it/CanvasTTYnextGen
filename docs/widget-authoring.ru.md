# Создание виджетов

[English](widget-authoring.md) · [Русский](widget-authoring.ru.md) · [Документация](README.ru.md)

Это руководство описывает доверенные виджеты на уровне исходного кода, компилируемые вместе с Raoden Loom. Для сторонних пакетов, устанавливаемых во время работы, используйте permissioned [runtime API плагинов](plugins.ru.md). Source-level путь остаётся правильным, когда нужен новый доверенный adapter в main process или изменение core ownership продукта.

## Выберите минимальную форму расширения

| Форма | Когда использовать | Типичный владелец |
|:--|:--|:--|
| Пассивный виджет Home | Часы, кнопка запуска, производная подпись или локальное для renderer представление, которое не потребляет ввод с колеса мыши | `features/home/` плюс чистый селектор |
| Виджет Home с источником в main | Использование у провайдера, состояние машины или другое значение, которому нужны файловая система, сеть, учётные данные или подпроцесс | общий контракт → сервис в main → IPC/preload → чистый селектор → компонент Home |
| Сущность канваса | Перемещаемый пространственный объект с мировой позицией, опциональным размером и поведением фокуса | отдельный feature-компонент, собранный в `WorkspaceCanvas` |

Не создавайте сервис в main ради данных, которые уже есть в типизированном состоянии renderer. Не запрашивайте привилегированные данные напрямую из React только потому, что так удобнее.

## Путь через границы процессов

Для виджета с источником в main двигайтесь в таком порядке:

1. Добавьте очищенный тип запроса/снапшота и имя IPC в [`src/shared/contracts.ts`](../src/shared/contracts.ts).
2. Создайте узкий адаптер или сервис в [`src/main/services/`](../src/main/services/), который владеет учётными данными, подпроцессами, таймаутами, валидацией, кэшем и освобождением ресурсов.
3. Зарегистрируйте один разрешённый обработчик в [`src/main/ipc/registerIpc.ts`](../src/main/ipc/registerIpc.ts).
4. Откройте только типизированную возможность через [`src/preload/index.ts`](../src/preload/index.ts). Никогда не отдавайте примитивы Node, сырой IPC, токены, cookies или ответы провайдера.
5. Преобразуйте снапшот в данные представления чистым селектором рядом с feature-владельцем.
6. Отрисуйте состояние в узком компоненте и подключите его из Home или `WorkspaceCanvas`.
7. Проверьте тестами нормализацию, поведение ошибок и устаревших данных и селектор — прежде чем смотреть реальный сценарий в Electron.

`App.tsx` — граница оркестрации. Фича может владеть своей исключительной возможностью, но не должна лезть в API несвязанных фич.

## Визуальный язык

Новый виджет должен выглядеть родной частью Raoden Loom:

- Отталкивайтесь от спокойного пространственного рабочего стола, а не от панели, забитой элементами управления.
- Используйте крупные плоские плитки, мягкие радиусы, сдержанные тени и свободные интервалы.
- Графит подходит операционным поверхностям вроде терминалов; шалфейный, розовый, голубой и бледно-жёлтый — спокойным акцентам канваса.
- Делайте подписи короткими, а иерархию — читаемой с первого взгляда и при зуме.
- Оставляйте одно очевидное основное действие. Не добавляйте декоративные точки-индикаторы, важные действия, доступные только по наведению, вложенные рамки и поясняющий микротекст вокруг самоочевидных элементов управления.
- Перехватывайте колесо мыши только когда поверхность действительно прокручивается или потребляет этот ввод. Пассивные виджеты Home должны сохранять зум канваса.
- Используйте официальные SVG Lucide, уже лежащие в [`assets/icons/lucide`](../src/renderer/src/assets/icons/lucide/), и задокументированные марки провайдеров из [`assets/providers`](../src/renderer/src/assets/providers/README.md). Не перерисовывайте иконки в TSX.
- Явно моделируйте `loading`, `available`, `stale`, `unavailable` и `error`. Отсутствие данных нельзя превращать в пустую полоску, ноль или ложный успех.
- Проверяйте читаемость в обычном масштабе и читаемость смысловых сводок при отдалении. Одинаковые сущности должны сохранять одинаковые шрифт и насыщенность.

У Home фиксированные правила владения: медиа-контролы остаются внутри `HomeMediaWidget`. Пользовательская конфигурация принадлежит разделам General, Appearance, Controls и Plugins в Settings, а runtime-поведение фичи — её компоненту или сервису. Прежде чем менять что-либо из этого, прочитайте [UI-контракт](UI_CONTRACT.ru.md).

## Бриф для другого AI-агента

Скопируйте его в задачу агента и замените поля в квадратных скобках:

```text
Добавь в Raoden Loom виджет [НАЗВАНИЕ], который показывает [ПОЛЬЗА ДЛЯ ПОЛЬЗОВАТЕЛЯ].

До правок прочитай docs/ARCHITECTURE.md и docs/UI_CONTRACT.md и найди ближайший
существующий feature-паттерн. Raoden Loom — Electron MVP с изоляцией контекста:
привилегированная работа остаётся в main, межпроцессные данные объявляются в
src/shared/contracts.ts, IPC разрешается явно, а preload отдаёт только
типизированную очищенную возможность.

Источник данных: [СТРУКТУРИРОВАННЫЙ ИСТОЧНИК]. Никогда не парси текст терминала/TUI
и не выдумывай значения. Явно отрисуй состояния loading, available, stale,
unavailable и error. Не отдавай учётные данные, сырые ответы провайдера, промпты
или неограниченную историю.

Визуальное направление: спокойный пространственный рабочий стол; крупная плоская
плитка; мягкий радиус; сдержанная тень; графитовые операционные поверхности с
шалфейными/розовыми/голубыми/жёлтыми акцентами; короткие подписи; читаемость при
зуме канваса. Используй готовые ресурсы Lucide и провайдеров из репозитория. Не
добавляй декоративные точки-индикаторы, основные действия, доступные только по
наведению, вложенные рамки или собственный SVG в TSX. Сохрани правила владения
колесом мыши.

Область: [HOME PASSIVE / HOME MAIN-BACKED / CANVAS ENTITY]. Добавь узкие тесты
нормализации и выбора состояния. Запусти npm test, npm run typecheck, npm run
build, затем проверь затронутый сценарий в реальном окне Electron. Не добавляй
пакеты.
```

## Пример структуры исходников

Это пример именования, а не ABI runtime-плагинов:

```text
src/shared/contracts.ts
src/main/services/SessionUsageService.ts
src/main/ipc/registerIpc.ts
src/preload/index.ts
src/renderer/src/features/session-usage/
├── SessionUsageWidget.tsx
├── sessionUsageModel.ts
└── sessionUsage.css
tests/session-usage.test.mjs
```

Сначала используйте существующие общие токены стилей и только потом добавляйте CSS feature. Если виджет относится к Home, впишите его в утверждённую логическую композицию, не меняя молча размеры Home и не перенося контролы другого feature.

## Критерии готовности

- Отображаемое значение прослеживается до конкретного структурированного источника.
- Привилегированный доступ остаётся в main; renderer получает очищенные типизированные данные.
- Отсутствующие, устаревшие и неудавшиеся чтения различимы между собой.
- У виджета есть явный владелец; он не дублирует Settings и медиа-контролы.
- Колесо мыши, фокус, перетаскивание и зум канваса не конфликтуют.
- Виджет читается в целевых масштабах и использует существующие ресурсы.
- Нормализация и поведение селектора покрыты узкими тестами.
- Проходят `npm test`, `npm run typecheck` и `npm run build`.
- Сценарий проверен в реальном окне Electron.

Пример готовой модели данных — в разделе [Метрики и телеметрия](metrics-and-telemetry.ru.md).
