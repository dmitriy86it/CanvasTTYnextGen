# Roadmap: оркестрация «Лид Codex → Исполнитель Claude»

Архитектура: [ARCHITECTURE-PROPOSAL](ARCHITECTURE-PROPOSAL.md). Направление развития: [Автоматический цикл задач](AUTOMATIC-TASK-CYCLE.md) (цель → план и условия приёмки → исполнение → проверки → независимое ревью → исправления → подтверждённое завершение); текущий этап — [рабочие пространства](implementation/workspaces-spec.md). Порядок развития: A условия приёмки и независимое ревью → B доска задач → C параллельные исполнители с проверкой объединения → D эксперимент [EXP-SPEC-01: спекулятивное выполнение задач](EXP-SPEC-01-speculative-execution.md) (запланирован; ожидает принятия этапов A–C; не запускался; возврат к нему — обязательный критерий завершения C). После внешней приёмки рабочих пространств — этап [переименования в Raoden Loom](implementation/rename-raoden-loom.md) (ранее CanvasTTY; данные и технические идентификаторы сохраняются). Доказательства: [VALIDATION-MATRIX](VALIDATION-MATRIX.md). Проблемы: [TROUBLESHOOTING](TROUBLESHOOTING.md).

### Точные границы проверки

- **Реальные модели выполняли только одноэтапные планы** (Р6 C1, R1, R3, Р13 N и L: один `checkpoint(1)`). Многоэтапный цикл с checkpoint каждого этапа проверен только на тестовых CLI: E2E Р9, E1.
- **R3 выполнен через SIGTERM процессу main.** Electron обрабатывает SIGTERM как `app.quit()` с тем же `before-quit`. Cmd+Q и пункт меню «Quit» отдельно не проверялись.
- **Аварии и потерянный ответ IPC проверены только на тестовых CLI** в неупакованной сборке: SIGKILL main во время хода и во время проверки, повтор команды (E3–E8). Реальных аварийных прогонов не было.
- **UI упакованной сборки проверен только реальной серией R1–R3.** Packaged smoke Р10 — встроенный mock и проверки в песочнице.
- **Расход.** $0.0871 — стоимость по данным Claude CLI только двух завершённых ходов исполнителя (R1 $0.0515, R3 $0.0356). **Это не полная стоимость серии.** Стоимость двух остановленных ходов Claude неизвестна. Codex стоимость не сообщает, известны только токены: R1 133 772, R2 52 763, R3 131 429.
- **Дистрибутивы не проверялись:** dmg/zip, подпись Developer ID, нотарификация, Gatekeeper на другой машине.

### Открытые ограничения (сохраняются после приёмки)

> С Р12 пункты про Seatbelt, `structured-edit` и забор результата из checkpoint относятся только к запускам, созданным до Р12 (и к режиму «отдельная копия»). Новые запуски работают в папке проекта с правами CLI пользователя. Их ограничения перечислены в [FIRST-USE.md](FIRST-USE.md).

- **Только macOS.** Проверки проекта требуют Seatbelt: на Linux run встаёт на `sandbox_unavailable`, Windows не поддерживается.
- **Claude-исполнитель в кандидатном режиме `structured-edit`.** Ограничения правок задаёт политика CLI, а не граница ОС.
- **При старте нет поиска оставшихся процессов**, если вся группа процессов приложения была убита.
- **Результат из checkpoint забирается только через Git.** Команды — `refs/canvastty/<runId>/stage-<n>` (ARCHITECTURE, «Как забрать изменения»; [FIRST-USE.md](FIRST-USE.md), §6). UI ссылки не показывает и ничего не сливает.
- **Реальные CLI сохраняют свои сессии в домашнем каталоге пользователя** (`~/.claude/projects/`, `~/.codex/sessions/`), вне `userData` приложения. Приложение это не ограничивает.
- Вне MVP без изменений: дистрибутивы с Developer ID и нотарификацией, runner для Linux, Windows, денежный лимит на run (у Codex его нет).

**Что делает серия:** создаёт `<base>/probe-<ts>-<rand>/` (репо с одним коммитом без пользовательского git-config и hooks, `home/`, `tmp/`, `schema.json`, `attempts/<id>/`); генерирует токены (`randomBytes(16)`) и `U1` (`randomUUID`); до запуска проверяет, что в заданиях B2/K2 нет ни токена, ни `TOKEN=`; передаёт `thread_id` из B1 в argv и `expectSessionId` B2; в real-режиме снимает `--version`. rc=0 только если все четыре пробы успешны.

**Успех пробы — все условия сразу** (каждое проваленное попадает в `failed[]` отчёта): `outcome=completed` (включает: доставка `ok`, нет причины остановки, группа процессов очищена, supervisor без ошибок и с кодом 0); `report.status=valid`; `token` = ожидаемому; `answer` = `"ok"` (B1/K1) или `"resumed"` (B2/K2); `sessionId` = ожидаемому (B1 — непустой); `stopCause=null`; `groupCleared=true`; `nextTurnAllowed=true`; для Claude — `system/init.tools` и `mcp_servers`, выведенные из флагов (`--tools ""` → `[]`, `--strict-mcp-config` без `--mcp-config` → `[]`), и `session_id=U1`.

**Остановка серии:** первая проба с любым проваленным условием, Stop, таймаут или SIGINT/SIGTERM скрипта (текущий ход получает Stop). Оставшиеся пробы — `skipped` с причиной. Повторов и дополнительных вызовов нет.

**Отчёт** (`series-report.json` и stdout): режим, версии CLI, по каждой пробе — `ran`, `ok`, `failed[]`, `outcome`, `stopCause`, `delivery.status`, `report.status`, `tokenMatch`, `answerOk`, `sessionOk`, модель (Claude — `system/init.model`, Codex — `-m` из argv), длительность, счётчики. Значений env, stderr и данных авторизации в отчёте нет.

**Среда:** `<PROBE>` — новый каталог в scratchpad; `<REPO>` = `<PROBE>/repo` — git-репо с одним файлом `README.md`, один коммит; `<PROBE>/home`, `<PROBE>/tmp` — пустые; `<PROBE>/schema.json` — схема ниже. `<TOKEN>`, `<TOKEN2>` — случайные строки, генерируются перед пробой; `<U1>` — новый UUID. `{REPORT_FILE}` подставляет `runTurn` (уникальный файл попытки).
