# Рабочие пространства проектов — контракт

Статус: контракт уточнён по решениям ревью (2026-09-28). Независимое ревью реализации проведено 2026-09-28:
11 дефектов и одно замечание о покрытии исправлены, остаются ограничения
([evidence/workspaces-review](../evidence/workspaces-review/README.md)). **Решение владельца (2026-09-28): приняты для
macOS с открытыми ограничениями** — p9b, «Бета2», перекрытое окно не проверено ([ROADMAP](../ROADMAP.md)); ограничения
этим не закрыты. Этап 13 этим не принимается.

Доска задач и параллельные исполнители в этап не входят. Их направление описано в
[Автоматическом цикле задач](../AUTOMATIC-TASK-CYCLE.md).

## 0. Исходное состояние кода

- **Холст и камера.** Холст один. Камера `CameraState` живёт только в React-состоянии и не сохраняется. Понятия
  «пространство» в модели нет.
- **Хранилища в `userData`:**
  - `settings.json` — v15: области, заметки, плагины, одна карточка Browser, HOME;
  - `terminal-sessions.json` — v1, пишется только при `restoreTerminalSessions`, по умолчанию выключено;
  - `browser-state.json` — вкладки;
  - `orchestration/canvas.json` — v1: агенты и связи со списками `runIds`.
- **Процессы.** Процессы и журналы живут в main и не зависят от renderer. Правила `link_busy` и `folder_busy`
  допускают один активный запуск на связь и один на папку.
- **Резервирование запуска.** `runId` сначала атомарно записывается в связь (`canvasStore.startOnLink`), только потом
  создаётся запуск. Повтор с тем же `requestId` отвечает идемпотентно.

## 1. Сущности

| Сущность | Что это | Идентичность |
|---|---|---|
| **Пространство** | Холст пользователя: карточки, камера, история запусков, имя, основная папка | `id` (строка); у «Общего холста» постоянный id `common` |
| **Папка проекта** | Каталог на диске: `cwd` терминала, `project` агента | realpath |
| **Worktree** | Рабочая копия одного запуска (`runs/<runId>/worktree`) | `runId` |

- **Принадлежность** определяет явное поле `workspaceId`, а не путь.
- **Основная папка** (`root`) только подставляется по умолчанию в диалоги новых карточек. Карточка с другой папкой в
  пространстве допустима.
- **Worktree** не становится пространством. Он принадлежит запуску.
- **Отсутствующий или неизвестный `workspaceId`** означает «Общий холст». Такая карточка видна там, а не теряется.

## 2. Данные

- **`userData/workspaces.json`** (новый файл, main):

  ```
  { v: 1, activeId, workspaces: [ { id, title, root, createdAt, closed, camera } ] }
  ```

  - `camera` — `{x, y, zoom} | null`; `null` означает камеру HOME при первом открытии.
  - Порядок в переключателе — порядок массива.
  - Запись атомарная: tmp, затем rename, через одну очередь.
- **Необязательное `workspaceId`** у существующих записей:
  - `SessionMetadata` и сохраняемая сессия;
  - `OrchestrationAgentCard`;
  - `CanvasRegion`, `StickyNote`, `PluginCanvasInstance`, `BrowserCanvasState`.

  Нормализаторы поле сохраняют. Версии `settings.json` (15), `terminal-sessions.json` и `canvas.json` (1) **не
  повышаются**: чтение без поля даёт `common`.
- **Владелец запуска** хранится в `canvas.json`: `owners: { [runId]: workspaceId }`.
  - Запись идёт **в той же атомарной записи**, что и резервирование `runId` в связи.
  - Отдельного шага «сохранить владельца» нет. Сбой записи означает `store_failed`: нет ни резервирования, ни
    владельца, ни запуска.
  - Сбой или перезапуск после записи: запуск либо создан, либо скрыт как несуществующий. При повторе с тем же
    `requestId` резервирование уже есть, `create` отвечает идемпотентно, владелец не меняется.
- **Владелец старого запуска:** `owners[runId]`, иначе пространство связи, где лежит `runId`, иначе `common`.
  - Перед переносом группы, удалением карточки или связи main в той же записи дописывает `owners` для всех `runIds`
    затронутых связей по их текущему пространству.
  - История не переезжает вслед за карточками.
- **Полей для задач и доски нет.**

## 3. Миграция

Порядок: сначала резервная копия, потом новый файл. Старые файлы миграция не переписывает. Противоречия с
`SETTINGS_VERSION` нет: версия не повышается.

1. **Когда.** В начале `initializeServices`, **до** создания `SettingsStore`, `TerminalManager`, `BrowserService` и
   менеджера оркестрации. Второй экземпляр исключает `requestSingleInstanceLock`. Очередей записи ещё нет, файлы
   неподвижны, и копия согласована.
2. **Признак готовности.** Если `workspaces.json` есть и корректен, миграция не нужна. Повреждённый файл отодвигается
   (`.damaged-<uuid>`), дальше выполняются шаги 3–5.
   - Не удалось отодвинуть → файл не трогается, пространства недоступны (как в шаге 7).
   - Файл более новой версии (`v > 1`) не считается повреждённым: он не трогается, пространства недоступны.
3. **Незавершённые попытки.** Оставшиеся `backup/*.partial` удаляются.
4. **Резервная копия.** В `backup/pre-workspaces-<время>.partial/` копируются `settings.json`,
   `terminal-sessions.json`, `browser-state.json`, `orchestration/canvas.json`, затем пишется `manifest.json` (по
   каждому файлу `copied` + sha256 или `absent`).
   - `ENOENT` означает отсутствующий необязательный файл.
   - Любая другая ошибка означает сбой.

   Готовая папка переименовывается без `.partial`.
5. **Точка фиксации.** Атомарно пишется `workspaces.json` с одним «Общим холстом» (`common`, `activeId = common`).
6. **Прерывание** до шага 5 → при следующем старте всё повторяется с шага 3. После шага 5 миграция завершена. Повтор
   идемпотентен.
7. **Сбой шагов 3–5.** `workspaces.json` не пишется. Приложение работает с одним «Общим холстом» в памяти. Создание,
   перенос и закрытие пространств main отклоняет (`workspaces_unavailable`), переключатель показывает причину.
   Следующий запуск пробует снова.

**Откат на старую сборку** проверен только в таких пределах. Проверка запускает `SettingsStore` и
`normalizePersistedTerminalSessions` из HEAD (`git archive HEAD`) на файлах, записанных новой сборкой:

- области, заметки, плагины, Browser и сохранённый терминал остаются, их координаты и размеры те же;
  остальные настройки не меняются;
- `workspaceId` снимается при чтении и пропадёт при первой записи файла старой сборкой. После повторного обновления
  такие записи оказываются в «Общем холсте»;
- старая сборка не читает `workspaces.json`.

**Не проверено:** `canvas.json`. Оркестрации нет в HEAD (она не закоммичена), поэтому прежний `canvasStore` запустить
нечем. Совместимость `owners` и `workspaceId` агентов при откате не заявляется.

## 4. Владение и правила main

- **Терминал.**
  - `workspaceId` задаётся при создании. Без него используется активное пространство: это нужно для запросов
    интеграций.
  - `terminal:setWorkspace` переносит работающий терминал без перезапуска: процесс, буфер и id сохраняются.
  - `terminal:stop` — остановка для «Остановить и скрыть»: сигнал, затем ожидание выхода (до 5 с). Ответ:
    - `exited` — выход подтверждён, только после этого сессия удаляется;
    - `absent` — у main нет записи о терминале с таким id. Это не подтверждение выхода: интерфейс показывает
      «закрыт, завершение не подтверждено» и автоматически не скрывает;
    - `kill_failed` — сигнал не отправлен;
    - `timeout` — выхода нет.

    При `kill_failed` и `timeout` сессия остаётся в main. Уже завершившийся терминал сразу `exited`, без сигнала.
    Выход в момент запроса (сигнал не прошёл, событие выхода пришло) — `exited`.
    Процесс, которому `stop` отправил сигнал, запись теряет только вместе со своим выходом: `absent` для него
    невозможен.
  - `terminal:dispose` — закрытие карточки: сигнал и удаление карточки без ожидания выхода, как раньше. Если сигнал
    не отправлен, сессия остаётся в main, карточка возвращается, вызывающий получает ошибку. Сигналом завершения для
    «Остановить и скрыть» `terminalRemoved` больше не служит. Если `stop` уже отправил сигнал живому процессу и
    выход не подтверждён, `dispose` отправляет сигнал, но запись оставляет: карточка удаляется при выходе процесса,
    а до него процесс управляем (повторный `stop` снова шлёт сигнал). В этом случае main помечает сессию
    `closeUnconfirmed` и шлёт событие сессии: карточка, которую renderer убрал при закрытии, возвращается с меткой
    «закрыт, завершение не подтверждено». Без опроса процессов и перезагрузки окна; метка не сохраняется на диск.
  - Неизвестный или закрытый пространство-адресат → отказ.
- **Агенты.**
  - `createAgent` требует существующее открытое пространство.
  - Связь карточек из разных пространств → `link_workspaces`.
- **Перенос группы агентов** — `moveAgentGroup(agentIds, workspaceId)`:
  - группа — компонент связности по связям;
  - переданный набор должен совпасть с группой, иначе `group_changed`. Это та группа, которую пользователь видел
    до подтверждения;
  - любая связь группы с незавершённым запуском (`preparing | running | pausing | paused | stopping`) → отказ
    `group_active_run`, пауза тоже считается незавершённым запуском;
  - запуск, журнал которого есть, но не читается, считается незавершённым (отказ, а не пропуск). То же при удалении
    связи и карточки;
  - в той же записи фиксируются `owners`.
- **Области, заметки, плагины, Browser.**
  - Поле пишет renderer через обычное сохранение настроек, main проверяет формат.
  - Browser один на приложение. Перенос только явным действием, вкладки (`browser-state.json`) не трогаются.
- **Закрытие пространства** (`closed = true`) ничего не останавливает.
  - Последнее открытое закрыть нельзя (`last_open_workspace`).
  - Если закрыто активное, активным становится первое открытое.
- **Удаление** разрешено только для пустого пространства. «Общий холст» не удаляется. Пустое означает, что нет:
  - терминалов;
  - агентов;
  - областей, заметок, плагинов, Browser;
  - **запусков с этим владельцем**.

  Иначе отказ `workspace_not_empty` или `workspace_has_history`. Пока main считает содержимое, пространство закрыто для
  новых карточек.
- **Крайний случай старых данных.** Резервирование, оставленное сборкой без `owners` (запуск не создан), при повторе
  после переноса группы получает пространство связи на момент повтора.
- **Камера** — `setCamera(id, camera)` с **явным id**. Запоздалая запись камеры A пишется в A и не трогает B. Числа
  проверяются на конечность, `zoom` — на диапазон.

## 5. Пользовательские действия

```
Переключатель (полоса над холстом): [Общий холст] [alpha ▶1 ⌨2 !1] [beta ▶1] [+] [⋯]
  ▶ запуски оркестрации в работе · ⌨ CLI-агенты в терминалах в работе · ! ждут человека
    (shell-терминалы не считаются работой, число открытых терминалов — в подсказке)
  клик / палитра «Пространство: …» / ⌘1…⌘9 (только macOS)
    → камера текущего сохраняется с его id → показываются карточки выбранного → восстанавливается его камера
      (процессы, подписки и данные не трогаются)
  [+] → выбрать папку → имя = basename; папка уже у пространства X → «Открыть X» / «Создать ещё одно»
  [⋯] → переименовать · основная папка · история запусков · разложить по пространствам… · скрытые · закрыть · удалить

Общий виджет активности: строка = пространство · проект · этап · кто · состояние
  запуск → пространство владельца → камера к ведущей карточке (если она есть) → панель запуска
           (итог, если завершён; вопрос или разрешение, если ждёт)
  терминал → его пространство → focusCamera
  «Последние результаты» и «История запусков» → запуск по runId: работает и без карточек и связи

Карточка → «Перенести в пространство…»:
  терминал — сразу, без перезапуска;
  агент — показывается вся связанная группа; незавершённый запуск → причина, кнопка неактивна, main тоже откажет;
  область / заметка / плагин / Browser — по одной
  раскладка переносимого сохраняется; если он накрыл бы карточку адресата (HOME тоже), весь набор сдвигается
  вправо до первого свободного места

Browser в другом пространстве → «Браузер открыт в пространстве X» · «Перейти» · «Перенести сюда»

Закрыть пространство → работы нет — скрыть; есть работа — диалог со списком запусков и терминалов:
  «Скрыть, работа продолжится» (по умолчанию)
  «Остановить и скрыть» → Stop каждому запуску, завершение каждого терминала; по каждому строка результата:
     останавливается (сигнал отправлен) / остановлен (main подтвердил выход; для запуска — завершённый статус) /
     ошибка (сигнал не отправлен, процесс остаётся под управлением main) / не завершился за 5 с (продолжает
     работать, под управлением main) / закрыт, завершение не подтверждено (`absent`) / состояние неизвестно;
     скрытие только если всё подтверждённо остановлено, иначе список остаётся с доступом к каждому
     неостановленному («Открыть») и «Скрыть, остальные продолжат работу» (ничего повторно не останавливает);
     если за это время в пространстве появилась новая работа, оно не скрывается и это сказано
  Запуск, известный по runId, но без снимка: «состояние загружается» или «не удалось получить состояние»,
     кнопка «Повторить»; работой он считается (диалог открывается), автоматического скрытия нет; если его
     состояние прочитано после «Остановить и скрыть», Stop отправляется тогда. Явное скрытие — с предупреждением,
     что результат этой работы не проверен
  Терминал с меткой `closeUnconfirmed` (в том числе shell) считается работой: диалог открывается и предлагает
     остановку, строка — «закрыт, завершение не подтверждено». «Открыть» у терминала переходит в его пространство
     и выделяет карточку; если карточки уже нет, диалог остаётся открытым и сообщает, что записи о терминале нет
  «Отмена» — ничего не меняет

Разложить по пространствам… (только отдельным действием) → предпросмотр групп по папке
  (терминалы и группы агентов; галочки сняты) → выбор пространства-адресата (новое или существующее)
  → «Перенести отмеченные». Без подтверждения ничего не переносится.
```

- **Камера** сохраняется через 500 мс после последнего изменения, при переключении и перед выгрузкой страницы.
  Запись всегда адресована пространству, в котором был жест.
  - Жест, начатый в A, заканчивается в A. При переключении прокрутка колесом, ждущая кадра, и перетаскивание холста,
    выделение рамкой или перенос группы отменяются до следующего кадра.
  - Изменение камеры помечено пространством, показанным в момент жеста. Изменение, пришедшее после переключения с
    меткой другого пространства, отбрасывается.
- **Окно в фоне** (свёрнуто или перекрыто). Chromium не рисует такую страницу и замедляет её таймеры. Работа, вывод и
  состояние при этом идут в main и в состоянии renderer; отстаёт только отрисовка: терминал дорисовывается при
  возвращении окна. Камера, сохранение которой ждало таймера, записывается с задержкой, но для своего пространства.
- **Скрытые карточки** не монтируются. После возврата терминал восстанавливает вывод из буфера main (`readBuffer`), как
  после перезагрузки: хранится не больше `MAX_SCROLLBACK_CHARS`.
- **Подписки на запуски** (`watch`) не зависят от активного пространства. Main держит одну подписку на страницу и
  запуск.
- **Горячие клавиши.** ⌘1…⌘9 только на macOS: xterm не передаёт ⌘ в pty, меню приложения этих сочетаний не использует.
  На Windows и Linux Ctrl+цифра — управляющие коды терминала, а Ctrl+Alt — AltGr раскладок, поэтому там только палитра
  и переключатель. Если пользователь назначил ⌘цифру на «Домой» или «Переименовать», действует его назначение. Пока фокус
  во встроенном Browser, ⌘цифра до окна не доходит.

## 6. Счётчики и статусы

Источники существующие:

- `terminal.list()` — `provider` и `status`;
- `orch.canvas` и снимки запусков;
- `activityRuns` / `runStatus`.

Счётчики:

- «▶ запуски»: запуски владельца в состояниях `starting | working | checking | waiting_agent | stopping`.
- «⌨ CLI»: терминалы с `provider ≠ terminal` в `status = working`.
- «! внимание»: запуски в `waiting_user` и терминалы в `needs_approval`.
- Открытый shell (`provider = terminal`) не считается работой.

Новой модели статуса, опроса процессов и сохранённых счётчиков нет.

## 7. Критерии приёмки

**Main и миграция (юнит-тесты на обезличенных фикстурах в tmp):**

- M1:
  - миграция не меняет байты `settings.json`, `terminal-sessions.json`, `browser-state.json`, `canvas.json`;
  - все карточки всех типов видны в `common` с прежними координатами, размерами и связями;
  - копия и manifest совпадают с исходными (sha256);
  - повтор ничего не меняет.
- M2:
  - прерывание после каждого шага (partial-копия, готовая копия без `workspaces.json`) → следующий старт завершает
    миграцию;
  - отсутствующий необязательный файл → `absent`;
  - ошибка чтения, отличная от ENOENT → миграция не выполнена, файлы не изменены, пространства недоступны.
- M3. Повреждённый `workspaces.json` → отодвинут, новая копия, все карточки в `common`.
- M4. Карточка с неизвестным `workspaceId` видна в `common`.
- M5. Откат: нормализаторы HEAD на файлах новой версии дают ровно описанные в §3 потери, без потери карточек
  (`canvas.json` не проверяется, см. §3).
- M6. Владелец запуска:
  - сбой записи резервирования → нет ни запуска, ни владельца;
  - сбой создания после записи → запуск скрыт, владелец не приписан другому пространству;
  - повтор `requestId` → один запуск, владелец прежний.
- M7:
  - перенос группы с незавершённым запуском, в том числе на паузе, → отказ в main;
  - после завершения перенос проходит, `owners` старых запусков прежние;
  - удаление связи или карточки сохраняет владельца истории.
- M8. Удаление пространства с историей или карточками → отказ; пустое удаляется; `common` не удаляется; последнее
  открытое не закрывается.

**UI (Electron, тестовые CLI, 1280×800 и 1440×900, реальные клики с проверкой попадания,
`scripts/smoke-workspaces-ui.mjs`):**

- W1. В пространствах A и B по связи и терминалу. Запуски A и B удерживаются одновременно. Счётчики A и B показывают
  запуск, shell не считается работой.
- W2. 10 переключений A↔B:
  - число стартов CLI не растёт;
  - pid терминалов прежние;
  - новых runId нет;
  - вывод, напечатанный в скрытом терминале, есть после возврата.
- W3:
  - камера каждого пространства восстанавливается после переключения, перезагрузки renderer и перезапуска
    приложения;
  - поздняя запись камеры A после переключения на B не меняет камеру B.
- W4. Вопрос в B, пока открыто A: у B появляется «!». Клик по строке виджета открывает B и панель с вопросом.
- W5. Запуск A завершается, пока открыто B:
  - итог доступен из виджета;
  - после перезапуска итог доступен из истории A;
  - повторных запусков нет.
- W6. Карточки B не видны в A: ни в DOM, ни при попадании указателя.
- W7. Перенос терминала без перезапуска: pid и вывод прежние.
- W8. Перенос группы агентов:
  - при незавершённом запуске — причина и отказ;
  - после завершения — вся группа переносится;
  - история запуска остаётся у A и открывается после удаления связи.
- W9. Закрытие A с работой:
  - «Скрыть» — работа идёт, строка в виджете открывает A;
  - «Остановить и скрыть» — результат по каждому участнику;
  - «Отмена» — без изменений.
- W10. Browser: в B видно, где он открыт; «Перенести сюда» сохраняет вкладку.
- W11. Окно в фоне, **без ключей Chromium**, которые держат его отрисованным (`scripts/smoke-workspaces-background.mjs`):
  - в свёрнутом окне запуск доходит до завершения, а все строки терминала попадают в буфер main;
  - после возвращения терминал показывает последнюю строку, а виджет — завершённый запуск;
  - камера после завершённого жеста сохраняется для своего пространства и возвращается после перезапуска;
  - прокрутка A, ждущая кадра, и перетаскивание холста A во время ⌘цифры не сдвигают и не записывают камеру B.

**Регрессии:**

- `smoke-activity-ui`, `smoke-orchestration-ui`, `smoke-native-ui`. Для сбоя перетаскивания и `outside the window` в
  `smoke-orchestration-ui` причина `outside the window` установлена и устранена (прокрутка `.workspace` фокусом,
  R-U04). Один случай неудачного перетаскивания (p9b) остаётся открытым наблюдением, автоповторов нет (см. evidence);
