# Понятная работа агентов: что сделано и следующие этапы

Статус: первый этап (активность, текущее действие, итог) принят внешним ревью с открытым замечанием: нестабилен
`smoke-orchestration-ui` (перетаскивание заголовка, вкладка history вне окна; причина не установлена). Этап 13 этим не
принимается, паритет с терминалом не доказан. Задание на рабочие пространства — `workspaces-spec.md`.

## Сделано в первом этапе

Одни правила отображения — `src/renderer/src/features/orchestration/runStatus.ts` — для трёх мест:

- **Виджет активности на HOME.** Терминальные сессии и запуски оркестрации вместе, с пометкой «Терминал» /
  «Оркестрация». Один запуск — одна строка (проект, этап, кто работает, состояние, причина ожидания), участники
  раскрываются внутри строки. Нажатие открывает существующий запуск. «Сейчас нет активных сессий» показывается только
  когда оба источника ответили; при загрузке — «Загрузка…», при ошибке — текст ошибки и «Повторить». Завершённые запуски —
  в блоке «Последние результаты» с кнопкой «Итог». Источник — состояние приложения (связи холста и их последние
  запуски), а не поиск процессов.
- **Карточки агентов.** Под состоянием — конкретное действие («Codex проверяет этап 3: …», «Claude закончил ход и ждёт
  ревью», «Требуется разрешение на команду»), время последнего события и «Нет новых событий N» после 30 с тишины
  работающего CLI. Только факты журнала и событий CLI; текст рассуждений не показывается; длинные строки обрезаются
  многоточием. Кнопка «Итог» у завершённого запуска.
- **Итог запуска.** Вкладка «Итог» в панели запуска (шире обычной, разворачивается на окно): цель, итоговое состояние и
  причина, этапы (выполнен / не выполнен / не проверен / не начат), что сделал исполнитель, заключение лида, команды
  проверки (отдельно от этапов; число тестов не заявляется), замечания и ограничения, где изменения, фактические commit,
  push и QA, следующий шаг — только если он есть в отчёте. Подтверждённое журналом и слова агента помечены по-разному.
  Нет сведений — «Не указано»; ошибка чтения — «Не удалось загрузить» и повтор. Модель не вызывается. Завершённый запуск
  открывается сразу на итоге; если запуск завершился, пока пользователь смотрел другую вкладку, появляется предложение
  открыть итог — вкладка и прокрутка не меняются.
- **Подробности.** Служебные hooks свёрнуты («Служебные события (hooks): N — Показать»), структурированные ответы в
  ленте — текстом и списками. Журнал и тексты читаются один раз и общие для виджета, карточек и панели.

## Следующие этапы (согласованное устройство)

### 1. Рабочее пространство проекта

У каждого проекта свой холст: его агенты, терминалы, задачи и история запусков. Виджет активности остаётся общим для
всех проектов и открывает нужное пространство. Правила отображения — те же (`runStatus.ts`), второго источника статуса
не появляется.

### 2. Доска задач

Направление и этапы: [Автоматический цикл задач](../AUTOMATIC-TASK-CYCLE.md) (этап B).

Колонки: очередь → работа → проверка → готово. У задачи — зависимости и причина блокировки (ждёт другую задачу, ответ
пользователя, разрешение, проверку). «Готово» — только после принятого лидом ревью и пройденных команд проверки, а не по
словам исполнителя. Статус карточки задачи берётся из того же состояния запуска, что и виджет.

### 3. Параллельные исполнители

Несколько исполнителей на разных задачах одного проекта: каждый в своём worktree, конфликты изменений выявляются до
объединения, объединённый результат проходит команды проверки заново. Итог показывает вклад каждого исполнителя и
проверку объединения отдельно.

Несколько процессов Claude — это не Agent Teams. Текущий адаптер запускает `claude -p`; настоящие Agent Teams требуют
отдельной проверки и интеграции. Права, модели и протоколы запуска в первом этапе не менялись.

## Проверки первого этапа

## Исправления по внешнему ревью (R1–R4)

- **R1, нумерация после перепланирования.** Названия этапов — по глобальному номеру (`stageTitleMap`): каждый план
  называет этапы начиная со своего `firstStage`, принятые этапы сохраняют название своего плана; план, чей текст не
  загружен, оставляет свои номера без названий. В итоге у этапа есть версия плана; непринятые этапы, заменённые новым
  планом, показаны отдельно вместе со своими ревью. Нумерация плана в обзоре панели («Этап N / всего») учитывает
  `firstStage`.
- **R2, полный перечень проверок.** Список обязательных команд берётся из состояния приложения (`progress.checks`),
  для старых журналов — из команд цели; журнал добавляет результаты и число попыток. Без известного перечня итог
  прямо говорит, что показаны только команды из журнала.
- **R3, промежуточные ревью.** Без финального ревью итог показывает последнее открытое ревью лида (вердикт, отчёт,
  замечания) и открытый вопрос. Ревью, закрытые принятием этапа, заменённые следующим ревью или перепланированием,
  собраны в «Прошлые ревью» с причиной.
- **R4, ошибки загрузки.** Ошибка журнала при уже прочитанных записях видна в итоге с «Повторить»; сведения помечены
  неполными, отсутствие данных в непрочитанной части — «Не загружено», а не «Не указано». Ошибка состояния запуска —
  ошибка с повтором в панели и на карточке (кнопка «Открыть запуск» остаётся). Повтор читает журнал с первой
  недостающей записи (`readJournal`), запусков и команд не создаёт.

## Исправления по повторному ревью

- **Неполный журнал не даёт отрицательных выводов.** Пока журнал читается или следующая страница не загрузилась,
  завершённый запуск без прочитанного финального ревью показан как «Запуск завершён. Подробности результата ещё не
  загружены», а не как неподтверждённая цель. Непринятые этапы — «состояние не загружено», счётчик этапов — «в
  прочитанной части журнала», попытки проверок — «не меньше N», последнее ревью — «последнее прочитанное, актуальность
  не подтверждена». Состояние из main (статус запуска, команды проверки, commit/push/QA) показывается как есть.
  В «Обзоре» факт «Цель принята финальным ревью» при неполном журнале — «не загружено».
- **Финальное ревью относится к своему плану.** Новый план переводит прежнее финальное ревью в историю («заменено
  новым планом», с версией плана); более позднее ревью заменяет более раннее финальное. Отчёт исполнителя и следующий
  шаг заменённого плана не выдаются за актуальные.
