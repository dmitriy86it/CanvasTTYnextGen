# План финальных реальных проверок через UI (для приёмки MVP)

Статус: **выполнен 2026-09-24** с разрешения пользователя (вся серия R1–R3, с уточнениями §8): R1–R3 засчитаны, 27/27. Результат — `evidence/real-ui/`. Packaged smoke Р10 и E2E Р9 работают на fake CLI и не заменяют эти проверки: в них нет ни одного хода реальной модели.

## 1. Что проверяется

Три сценария через настоящее окно CanvasTTY с реальными CLI:

| # | Сценарий | Ожидаемый итог |
|---|---|---|
| R1 | Новая цель на связи «Codex (лид) → Claude (исполнитель)» до `completed` | план → ход исполнителя → проверка → ревью → checkpoint → финальное ревью → `completed` |
| R2 | «Стоп» во время реального хода исполнителя | ход `stopped`, run `stopped`, после Stop нет ни одного хода, CLI-процессов не осталось |
| R3 | Штатный выход из приложения во время реального хода, повторный запуск | до выхода ход остановлен, run `paused(user_request)`; после запуска ничего не продолжается само, карточки, связь и история на месте; «Продолжить» доводит run до `completed` (или «Стоп» — см. §6) |

## 2. Окружение

- **Сборка.** Упакованное приложение из **нового временного каталога**, как в Р10 (`electron-builder --dir -c.directories.output=<tmp>`), после `npm run build`. `release/`, установленное приложение и профиль пользователя не используются.
- **Профиль приложения:**
  - запуск `<tmp>/release/mac-arm64/CanvasTTY.app/Contents/MacOS/CanvasTTY --user-data-dir=/tmp/cto-real-ui-<дата>/user-data`;
  - `HOME` — настоящий, иначе CLI не найдут свою авторизацию;
  - переменные `CANVASTTY_ORCHESTRATION_*` не задаются, а упакованная сборка их всё равно игнорирует (Р10).
- **CLI — проверено `--version` на 2026-09-24 (без модельных запросов):**
  - `~/.local/bin/codex` — `codex-cli 0.155.1`;
  - `~/.local/bin/claude` — `2.1.281 (Claude Code)`.
  
  Приложение отказывает любой другой версии (`unsupported_version`) до создания run. Перед проверкой версии сверяются ещё раз.
- **Модели** зафиксированы в приложении (`APP_PROVIDERS`, `manager.ts`):
  - лид — Codex `gpt-6-astra`, `model_reasoning_effort="high"`, режим `structured-readonly`;
  - исполнитель — Claude `claude-sonnet-5`, режим `structured-edit` (кандидатный, Р6), `--max-budget-usd 1` на каждый ход исполнителя.
- **Проект** — новый временный Git-репозиторий `/tmp/cto-real-ui-<дата>/project`:
  - копия `tests/fixtures/orchestration/series-project` (проект C1 реальной серии Р6);
  - `git init -b main`, один коммит;
  - в корне должны быть `package-lock.json` (есть) и настоящая папка `node_modules`, иначе будет отказ `deps_unavailable`: создать `node_modules/.package-lock.json` с `{}`, как в `real-series.mjs`. `node_modules/` в `.gitignore` проекта, поэтому в baseline не попадает;
  - рабочее дерево чистое: baseline копирует и незакоммиченные файлы.

  Перед стартом фиксируются: `git rev-parse HEAD`, `git for-each-ref`, `git status --porcelain --untracked-files=all`, sha256 рабочих файлов (как в E2E Р9).

## 3. Цель (R1; для R2 и R3 та же)

- **Задача:** «Add a function clamp(x, lo, hi) in src/clamp.mjs (ES module, named export) that returns x limited to [lo, hi] and throws RangeError when lo > hi. Add a unit test tests/clamp.test.mjs. Do not modify tests/clamp.accept.test.mjs.»
- **Критерии (по строке):**
  - tests/clamp.accept.test.mjs passes unchanged
  - all tests pass
  - no files outside src/ and tests/ change
- **Проверки:** `node-test` (`node --test`, запускает и приёмочный тест).
- **Лимиты в диалоге:** ходы 8, раундов на этап 2, перепланирований 1, время 20 мин. Лимиты хода по умолчанию: лид 20 мин, исполнитель 45 мин; в UI они не задаются.
- **«Показать план»** выключено (по умолчанию).

## 4. Бюджет

| Сценарий | Ожидаемо вызовов | Предел (остановка) |
|---|---|---|
| R1 | Codex 3 (план, ревью, финальное ревью) + Claude 1 = 4 | 8 ходов (лимит run) |
| R2 | Codex 1 + Claude 1 (остановлен) = 2 | 3 |
| R3 | до выхода Codex 1 + Claude 1; после «Продолжить» Claude 1 + Codex 2 = 5 | 8 ходов (лимит run) |
| Всего | ≈ 11 | **19 модельных вызовов**, затем остановка серии |

- **Claude.** Не более $1 на ход (`--max-budget-usd`, ограничение CLI); при пределе 19 вызовов — не более ~$8 по Claude.
- **Codex.** Денежного лимита на ход в CLI нет. Расход ограничивают лимит ходов run, время run (20 мин) и лимит хода лида (20 мин).
- **Время.** Около 60 минут на всю серию.

## 5. Порядок и что фиксировать

1. **Подготовка.** Проверить версии CLI, собрать приложение во временный каталог, создать проект и снять его состояние.
2. **R1.**
   - Запустить приложение. Правый клик по холсту → «Агент Codex (лид)» и «Агент Claude (исполнитель)» на папку проекта. Связать портом.
   - «Новая цель», поля из §3, «Старт». Дождаться `completed`.
   - Зафиксировать: снимки (связь, панель во время хода исполнителя, `completed` с историей); `journal.jsonl`; порядок операций; `checkpoint.created`; ссылки `refs/canvastty/<runId>/*` в проекте.
   - Сверить состояние проекта: HEAD, ветки, `git status` и файлы без изменений.
   - Сверить содержимое checkpoint: изменения только в `src/` и `tests/`; `tests/clamp.accept.test.mjs` не изменён (сравнить git blob).
3. **R2.**
   - «Новая цель» на той же связи. Когда карточка Claude покажет «Работает», нажать «Стоп».
   - Зафиксировать: `turn.finished(stopped)`, `stopped`; за 60 с после `command.received(stop)` нет `orch.turn`/`turn.intent`/`check.started`; процессов `codex`/`claude`, запущенных приложением, нет (`ps` по дереву main до и после).
4. **R3.**
   - «Новая цель». Когда Claude «Работает», закрыть приложение штатно (Cmd+Q).
   - Зафиксировать: выход с кодом 0; ход остановлен; run `paused(user_request)`; процессов CLI не осталось.
   - Запустить приложение с тем же `--user-data-dir`. Карточки, связь и история на месте. За 60 с ничего не запущено (журнал не растёт, новых процессов CLI нет).
   - «Продолжить» → run доходит до `completed`, после чего сверка как в R1.
5. **Отчёт.** Обезличенный: пути `~`/`<tmp>`, без содержимого авторизации и без полных ответов моделей. Туда входят версии, модели, число вызовов по провайдерам, стоимость Claude из событий `result` (если CLI её сообщает), длительности, снимки и журналы. Каталог `docs/agent-orchestration/evidence/real-ui/`.

## 6. Условия остановки (без повторов и без поднятия лимитов)

Серия останавливается, run — «Стоп», и ничего не повторяется, если:

- версия CLI не совпадает, или приложение отказало до создания run;
- run перешёл в `failed` или в паузу, которую сценарий не ожидает: `lead_modified_tree`, `permission_denied`, `loop_suspected`, `limit_reached`, `environment_error`, `sandbox_unavailable`, `shared_git_tampered`, `journal_corrupt`, `invalid_report`, `protocol_error`, `outcome_unknown`;
- изменились HEAD, ветки, индекс или рабочие файлы исходного проекта, либо появились ссылки вне `refs/canvastty/<runId>/`;
- после Stop или выхода начался новый ход, либо остался процесс CLI;
- число модельных вызовов достигло 19, или время серии превысило 90 минут;
- исполнитель изменил `tests/clamp.accept.test.mjs` или файлы вне `src/` и `tests/`.

В R3 при `outcome_unknown` вместо `paused(user_request)` — остановка и разбор, без «Повторить ход».

## 7. Вне плана

Авария (SIGKILL) во время реального хода и восстановление «Повторить ход» — отдельное согласование. На fake CLI это проверено в E2E Р9 (E3–E8). Не входят в план: Linux, packaged-сборка с подписью Developer ID и нотарификацией, публикация.

## 8. Уточнения пользователя перед стартом (2026-09-24)

- **Лимиты ходов в диалоге каждого запуска:** R1 — 8, R2 — 3, R3 — 8. Раундов на этап 2, перепланирований 1, время run 20 мин.
- **Серия:**
  - не больше 19 ходов оркестратора и 90 минут;
  - ход — это вызов CLI, а не отдельное обращение к модели внутри него: число внутренних запросов CLI не ограничено этим счётом.
- **Расход:**
  - Claude сохраняет `--max-budget-usd 1` на ход;
  - общая стоимость **не** объявляется ограниченной $8: у Codex денежного потолка нет;
  - стоимость указывается только по данным, которые сохранил CLI или приложение.
- **Сборка** — проверенная в Р10 `/private/tmp/canvastty-r10-pkg-wrc5/`. Отдельный временный userData и новый временный Git-проект; установленное приложение, `release/` и проекты пользователя не меняются. Авторизация CLI — существующая, её содержимое не выводится и не копируется.
- **Версии CLI** проверяются до модельных запросов. При несовпадении серия останавливается; версии, модели, права и лимиты автоматически не меняются.
- **R2 и R3 засчитываются**, только если до вмешательства зафиксирован живой процесс Claude-хода (pid и команда в дереве main, `turn.intent` без `turn.finished`), а ход завершился именно из-за вмешательства. Иначе сценарий не засчитывается, и дополнительный запуск не создаётся.
- **Действия пользователя** выполняются через окно (события мыши через DevTools-протокол, как в E2E). Журнал, процессы и git только читаются.
- **Штатный выход в R3** — SIGTERM процессу main. Electron обрабатывает его как `app.quit()`: тот же `before-quit` и та же остановка сервисов, что у «Quit»/Cmd+Q. Меню приложения синтетическими событиями DevTools недоступно. Это не авария: на репетиции с тестовыми CLI выход дал код 0 и `paused(user_request)`.
- **Драйвер:** `scripts/real-ui-series.mjs --real --app <.app>`. Режим `--rehearse` — тот же сценарий на dev-сборке с тестовыми CLI, без моделей; перед серией он пройден 27/27.
- **Остановка серии** — при первом неожиданном отказе, нарушении критериев или исчерпании лимита. Лимиты не повышаются, сценарии не повторяются, приложение посреди серии не исправляется. Аварийные реальные прогоны и публикация не разрешены.
