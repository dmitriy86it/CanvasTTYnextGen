1. S3 запущен на 8-й секунде. Codex-лид составил план, запуск встал на плановую паузу `plan_review`, драйвер нажал «Продолжить» (43 с).

   ```
   cat > src/duration.mjs <<'EOF' … EOF
   cat > tests/duration.test.mjs <<'EOF' … EOF
   npm test 2>&1 | tail -12; git status --short
   ```

   Полный текст лежит в `pending/9cb12d3e-….json`.
3. Правило ответов запрос не распознало. Драйвер оставил его ожидающим в панели и записал полный запрос в `pending/`. Механическая предпроверка (`heredocWrites`) — `ok`:
   - cwd — сам проект;
   - пишутся только новые `src/duration.mjs` и `tests/duration.test.mjs`;
   - разделители heredoc в кавычках, симлинков нет;
   - остаток — `npm test | tail` и `git status`.
4. **Координатор решение не записал.** Уведомление о запросе (строка журнала на 52,8 с) дошло до координатора только вместе с событием на 1208 с. Сам pending-файл записан вовремя, в 18:24:38 по местному времени. Почему уведомление задержалось, не установлено. Это сбой проведения серии на стороне координатора, а не приложения или CLI.
5. В 11:43:53 UTC сработал лимит приложения `runMin = 20`. Приложение сняло запрос (`permission_decided`), CLI получил отказ, ход завершился `stopped`, запуск перешёл в `paused(limit_reached)`. Драйвер увидел, что запрос больше не ожидает (`stale`), и остановил серию, не нажимая «Разрешить».
