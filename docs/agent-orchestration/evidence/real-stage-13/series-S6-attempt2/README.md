## Что изменилось перед попыткой

Попытка 1 (`series-S5-S6-attempt1`) остановилась на блокировке push. Причина: результат сверки адресов `origin` читался из смешанного вывода `$SHELL -ilc`, куда попадал шум `~/.zshrc` пользователя.

**Исправление.** Выбран выделенный канал результата: тот же приём, что уже работал для `$CANVASTTY_QA_RESULT`.
- Stdout машинной git-команды перенаправляется `>|` в свежий файл `runs/<runId>/finish/<uuid>-<i>.out`. Путь к файлу указан прямо в строке команды, а не в переменной окружения, которую rc мог бы переопределить.
- Затрагиваются: `get-url --all`, `get-url --push --all`, `rev-parse HEAD` после commit, `git log` поиска коммита при восстановлении, `ls-remote`.
- Файл читается только при `exit 0`, без Stop, таймаута и ошибки запуска. Он создаётся для каждой попытки заново (`wx`, `0600`), не открывается по symlink, результат больше 64 КБ считается неполным. После попытки файл удаляется.
- Вывод shell по-прежнему сохраняется как диагностика.
- Команды пользователя (hooks, signing, credentials, окружение) не менялись.

Почему не фильтр и не «последняя строка»: rc может печатать что угодно в тот же stdout, в том числе правдоподобный SHA или строку `<sha>\trefs/heads/<b>`. Это показывает регрессионный тест 7.

**По ревью закрыто:**
- если в профиле нет сохранённого адреса, push блокируется, а не идёт без сверки;
- сбой запроса адреса отличается от настоящего расхождения адресов;
- неподтверждённый коммит больше не записывается как «nothing to commit»;
- `output.tail` в `shellRun` теперь содержит последние 2000 символов любого вывода, и короткая диагностика не пропадает.

## Открытые ограничения (не исправлялись в этой задаче)

- **insteadOf.** Разрешённый адрес сохраняется как сырой `remote.<name>.url` (`profile.ts:84`), без раскрытия `insteadOf`. Если у пользователя есть глобальный `url.….insteadOf` для этого адреса, сверка всегда даст расхождение и push будет заблокирован. Отказ безопасный, но неудобный.
- **fish.** `>|` — синтаксис POSIX-shell и zsh. В fish, по анализу синтаксиса (fish не установлен, не проверено), commit может записаться как `failed` вместо `unknown`; push при этом не начнётся. tcsh/csh не проходят снятие окружения (`-ilc`), прогон не создаётся.
- Файлы результатов, оставшиеся после аварийного завершения, никогда не читаются.

Этот результат относится к S6 в описанной среде. Общий паритет с терминалом он не доказывает.
