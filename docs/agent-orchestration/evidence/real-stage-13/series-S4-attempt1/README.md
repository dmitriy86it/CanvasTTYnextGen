# Реальный S4, попытка 1 (2026-09-26)

**Итог:**
- **S4C (MCP-форма у Claude-исполнителя) — пройден**, проверки драйвера 20/20.
- **S4X (MCP-форма у Codex-лида) — заблокирован** проверкой драйвера перед стартом, до первого хода модели. Причина — неверная калибровка этой проверки в драйвере (описана ниже), не отказ Codex.

- **Верный ответ.** Сервер получил ровно те значения, что введены в форму.
- **Отказ.** Форма `web` отклонена, сервер получил `action: decline`.
- **Результат.** Оба вызова `mcp__release-form__release_ticket` завершились успешно. `release/receipts.txt` построчно и целиком совпадает со строками `text` сервера:

## S4X — форма MCP у Codex-лида: **заблокирован до модели**

Длительность — 14 с (`S4X-run/`). Ходов 0, вмешательств 0, расхода моделей нет. Запуск в приложении не создавался.

**Что произошло.** Драйвер перед стартом читает строку MCP из «Проверить окружение» приложения и требует для провайдера под проверкой статус `connected`/`ready`/`running`/`enabled`. Для Codex приложение показало:

```
release-form (unsupported)
```

Такой же статус там у всех 12 серверов Codex. Драйвер остановил вариант: `S4X blocked: codex does not report release-form as ready (unsupported); no model turn`.

**Причина — калибровка проверки в драйвере, а не отказ Codex.**
- Проверка окружения Codex в приложении (`probe.ts:149–156`) вызывает `mcpServerStatus/list` без треда. Тогда `runtimeStatus` пуст, и строка показывает `authStatus`. Для stdio-серверов `authStatus` — `unsupported`, то есть «вход не поддерживается». О готовности сервера это ничего не говорит.
- Сам `release-form` в списке есть, значит проектная конфигурация загружена и сервер обнаружен. В журнале сервера за время этой проверки есть `initialize` от `codex-mcp-client 0.155.1` (`S4X-run/mcp-elicit-S4X.jsonl`, 18:59:10).
- Проба без модели на том же пути до прогона показала `runtimeStatus connected`. Значит, мешало только правило остановки, само подключение работало.
- В репетиции тестовые CLI отдают фиксированный список, и проверка там не показательна (`gateNote`). Калибровку `S4_READY` под реальные статусы Codex нужно было сделать до реального прогона. Это не было сделано.

По условиям задачи посреди серии код не исправлялся, S4X не повторялся.
