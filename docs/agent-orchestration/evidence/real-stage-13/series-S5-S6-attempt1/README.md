### Причина блокировки push (дефект приложения, не исправлялся)

Перед push приложение сверяет адреса `origin`. Для этого оно выполняет `git remote get-url --all origin && git remote get-url --push --all origin` через `$SHELL -ilc` (`orchestrationService.ts:1034`), затем `remoteUrlsMatch` (`finish.ts:36`) требует, чтобы **каждая** непустая строка вывода совпадала с разрешённым адресом.

`zsh -ilc` пользователя при запуске без терминала печатает строки из `~/.zshrc`:
- `(anon):setopt:7: can't change option: monitor`;
- блок `[ERROR]: gitstatus failed to initialize.`

Эти строки попадают в тот же вывод. Воспроизведено на сохранённом worktree, файл `S6/remote-url-check-repro.txt`: после шума идут две строки ровно с разрешённым адресом. Тот же шум виден в сохранённом выводе подготовки S5 и S6 (`texts/`).

В репетиции login-shell тестовый и ничего лишнего не печатает, поэтому дефект там не проявился. Проверка адреса ошибается в безопасную сторону: push не выполнен, ничего лишнего не отправлено. Но в окружении пользователя с таким `.zshrc` push из S6 невозможен.
