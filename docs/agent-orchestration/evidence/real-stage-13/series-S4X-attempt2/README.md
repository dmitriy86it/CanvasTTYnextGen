**Итог: S4X (MCP-форма у Codex-лида) пройден.** Проверки драйвера — 20/20. Перед первым ходом модели прошла новая проверка готовности. Отказов не было, посреди прогона ничего не исправлялось, повторов не было.

Попытка 1 (`series-S4-attempt1`) остановилась до модели. Проверка драйвера приняла `authStatus` `unsupported` из пробы без треда за состояние сервера.

## Исправление перед попыткой

**Проба приложения** (`probe.ts`, `shared/orchestration.ts`, `ProjectSettings.tsx`).
- MCP-сервер теперь описывается отдельными полями: обнаружен (есть в списке), `connection` (`runtimeStatus` или `null`), `auth` (`authStatus`), `tools`.
- Строка `runtimeStatus || authStatus` удалена. Без `runtimeStatus` интерфейс пишет «Подключение не проверено», а `auth` показывается отдельно.
- У элементов списка есть data-атрибуты этих полей.

**Готовность одного сервера — только по явному запросу** `probe(linkId, { mcpReady })`. Запрос проверяется в main: лишние поля и нестроковое имя отклоняются. Проба запускается тем же исполняемым файлом, в том же окружении и в той же папке проекта, что приложение (`rt.executables`, `rt.env`). Порядок:
1. `config/read {includeLayers}`: слой проекта этой папки, `disabledReason` и сервер в самом слое (`inProjectLayer`) и в эффективной конфигурации (`inConfig`).
2. `mcpServerStatus/list` без треда.
3. Только если слой включён и сервер есть в слое, в конфигурации и в списке — `thread/start {cwd, ephemeral: true}` без turn и опрос списка треда, пока состояние не установится.

В недоверенной папке тред не запускается никогда. Любой непустой `disabledReason`, не только строка, выключает слой. После пробы группа процессов завершается.

**Проверка драйвера перед стартом** (`scripts/s4-gate.mjs`). Она решает по структурным полям и журналу сервера, текст интерфейса не разбирает. Для Codex одновременно должны выполняться:
- слой `enabled` без `disabledReason`;
- `release-form` задан в слое проекта и есть в эффективной конфигурации;
- тред запущен, `release_ticket` обнаружен, `connection === "connected"`;
- ошибки и таймаута нет;
- в журнале сервера есть `initialize` от `codex-mcp-client`, записанный не раньше начала этой пробы.

`unsupported` не считается успехом. Прежнее правило `S4_READY` и исключение «в репетиции проверка непоказательна» удалены.

**Тестовые CLI** воспроизводят ответы Codex.
- Тестовый Codex:
  - слой проекта (без доверия — с `disabledReason`);
  - без треда: `authStatus unsupported`, `runtimeStatus` нет;
  - в треде: настоящее подключение к серверу (`initialize` + `tools/list`), `connected` с инструментами.
- Тестовый Claude подключает серверы проекта на `mcp_status`.
