# «Остановить и скрыть»: подтверждение остановки (2026-09-28)

Повод — внешнее ревью. Приёмка этим документом не объявляется. Контракт обновлён в
[workspaces-spec.md](../../../implementation/workspaces-spec.md) §4 (`terminal:stop`, `terminal:dispose`) и §5.

## Дефекты

1. **Исчезновение терминала считалось подтверждением остановки.**
   - `TerminalManager.dispose` удалял сессию до `process.kill()`, проглатывал ошибку сигнала и отправлял
     `terminalRemoved`.
   - `CloseDialog` считал исчезновение сессии признаком «остановлен».
   - Последствия:
     - терминал, чей процесс не получил сигнал, отмечался остановленным, пространство скрывалось, а живой процесс
       выпадал из управления;
     - процесс, получивший сигнал, но не завершившийся, тоже считался остановленным.
2. **Запуск без снимка считался отсутствием работы.**
   - `closeHasWork` и список диалога брали только запуски с незавершённым статусом из снимка.
   - Известный `runId`, чей снимок ещё загружается или не читается, не открывал диалог.
   - При «Остановить и скрыть» такой запуск получал «ошибку» без повторной попытки.

## Исправление

- **main.**
  - Новая операция `terminal:stop` (`TerminalManager.stop`). Результат по-прежнему попадает в `SessionMetadata`
    через событие сессии; отдельного хранения нет.
  - `dispose`:
    - при ошибке сигнала больше не теряет живой процесс: сессия остаётся, карточка возвращается событием сессии,
      вызывающий получает ошибку;
    - завершившийся терминал закрывается без сигнала;
    - `disposeAll` при выходе продолжает с остальными.
- **renderer.**
  - `CloseDialog` вызывает `controls.stopSession` и ставит «остановлен» только по ответу `exited` (до исправления гонки
    — и по `absent`, см. «Гонка `stop` и `dispose`»). Для `timeout` и `kill_failed` — отдельные состояния с «Открыть». Автоматического скрытия нет, пока не все
    подтверждённо остановлены.
  - Запуск без снимка:
    - показывается как «состояние загружается» или «не удалось получить состояние» с «Повторить»;
    - считается работой;
    - если после «Остановить и скрыть» его состояние прочитано, ему отправляется Stop;
    - явное скрытие сопровождается предупреждением.
  - `closeHasWork` считает работой известный запуск без снимка.

**Изменение контракта для внешнего файла.** `/private/tmp/raoden-workspaces-close-review.test.mjs` сохранён
неизменным, SHA-256 — в `external-files-sha256.txt`. Он проверяет `dispose`.

## Гонка `stop` и `dispose` (внешнее ревью, 2026-09-28)

**Дефект.** `stop(id)` отправлял сигнал и ждал выхода. Параллельный `dispose(id)` удалял запись без подтверждения
выхода, `stop` отвечал `absent`, `CloseDialog` считал `absent` «остановлен» и мог скрыть пространство, хотя процесс
работал. Ссылка на живой процесс при этом терялась.

**Репро:** `/private/tmp/raoden-terminal-stop-race-review.test.mjs`, файл не изменялся (SHA-256 в
`race/final-summary.txt`).
- До: 1 из 2, `still-live process produced absent; CloseDialog maps this to stopped and permits automatic hiding`
  (`race/external-repro-before.txt`).
- После: 2 из 2 (`race/external-repro-after.txt`).

**Исправление.**
- **main, согласование `stop` и `dispose`.** `stop`, отправив сигнал живому процессу, помечает сессию как ожидающую
  выхода. `dispose` такой сессии отправляет сигнал, но запись не удаляет, а помечает «удалить при выходе». Запись
  уходит (с `terminalRemoved`) только в обработчике выхода процесса. До выхода процесс в `list`, повторный `stop`
  снова шлёт сигнал и ждёт, повторный `dispose` снова оставляет запись. Если сигнал `stop` не прошёл
  (`kill_failed`), пометка снимается и обычное закрытие карточки работает как раньше.
- **Смысл ответов.** `absent` — у main нет записи о таком id в момент вызова, не подтверждение. Для процесса,
  который `stop` наблюдал живым, `absent` невозможен: `stop` ждёт выхода и отвечает `exited` или `timeout`.
  Остановку подтверждает только `exited` — событие выхода самого процесса.
- **renderer.** `absent` → «закрыт, завершение не подтверждено»: с «Открыть», без автоматического скрытия. Явное
  «Скрыть, остальные продолжат» сохранено.
- Обычный `dispose` без предшествующего `stop` не менялся: сигнал и удаление карточки.

**Проверки.**
- `tests/terminal-stop.test.mjs` — 11 тестов. Прежний тест, ожидавший `absent` после удаления работающей сессии,
  заменён. Новые:
  - неизвестный id → `absent`;
  - `dispose` во время `stop` → `timeout`, запись в main, `terminalRemoved` нет;
  - поздний выход после этого → запись удалена;
  - выход, пока `stop` ещё ждёт → `exited`;
  - повторное обращение после гонки: второй `stop` снова сигналит (`timeout`), второй `dispose` запись оставляет,
    третий `stop` с выходом → `exited`, после него `absent`;
  - сигнал `stop` не прошёл → последующий успешный `dispose` удаляет карточку, как раньше.

**Ограничение (закрыто следующим разделом).** Карточку, закрытую во время `stop`, renderer убирает сразу (прежнее поведение `disposeSession`), а

приложения (`disposeAll`). Установлено по коду, стендом не проверялось.

## Карточка живого терминала после неподтверждённой остановки (внешнее ревью, 2026-09-28)

**Дефект.** `stop` получил `timeout`, процесс жив. Пользователь закрывает диалог, затем карточку. Main сохраняет
сессию до выхода (предыдущий раздел), но `App.disposeSession` сразу убирает карточку из renderer, а main не шлёт
ничего, что вернуло бы её. Карточки нет, `closeHasWork` при повторном закрытии пространства — `false`. Через
интерфейс процесс не увидеть и не остановить.

**Репро:** `/private/tmp/raoden-stop-card-visibility-review.test.mjs`, не изменялся (SHA-256 в
`card-visibility/final-summary.txt`). Он выполняет настоящий обработчик из `App.tsx`.
- До (изменения этого раздела в `TerminalManager` и `workspaceModel` временно откатаны): 0 из 1,
  `{ visible: false, asks: false }` (`card-visibility/external-visibility-before.txt`).
- После: 1 из 1. Репро гонки `stop`/`dispose` — по-прежнему 2 из 2.

**Исправление.**
- **main.** Когда `dispose` оставляет запись живого процесса (его уже сигналил `stop`, выход не подтверждён),
  сессия помечается `closeUnconfirmed` и main шлёт событие сессии. Renderer применяет его как любое другое:
  карточка, убранная при закрытии, возвращается. Опроса процессов нет, перезагрузка окна не нужна, метка на диск
  не сохраняется.
- **Карточка.** Метка «закрыт, завершение не подтверждено» в заголовке и в свёрнутом виде; остановленным терминал
  не показывается. Подтверждённый выход удаляет карточку штатно (`terminalRemoved` — последнее событие, повторного
  появления нет).
- **Закрытие пространства.** `closeHasWork` считает работой живой терминал с меткой, в том числе shell. Диалог
  открывается, предлагает остановку, строка — «закрыт, завершение не подтверждено».
- **«Открыть».** У терминала — переход в его пространство и выделение карточки (`WorkspaceControls.openSession`).
  Раньше диалог только переключал пространство и закрывался, даже если карточки не было. Если карточки нет, диалог
  остаётся и сообщает: «У приложения нет записи об этом терминале…».
- Обычное закрытие карточки без предшествующего `stop` и закрытие при ошибке сигнала не менялись.

  остаются открытыми.
- **Предел ожидания выхода — 5 с**, не настраивается. Процесс, который завершается дольше, показывается как
  «не завершился» и остаётся под управлением.
- **Закрытие карточки через `dispose`** по-прежнему не ждёт выхода (исключение — процесс, которому `stop` уже
  отправил сигнал, см. «Гонка `stop` и `dispose`»). Карточка процесса, получившего сигнал, но не
  завершившегося, исчезает. Процесс при этом продолжает жить. Это прежняя семантика закрытия карточки, её не менял.
- **Стенд компонента** проверяет `CloseDialog` вне полного приложения, с управляемыми ответами оркестрации. Путь в
  полном приложении с настоящим shell проверяет `smoke-workspaces-ui` (W9).
