# Оркестрация Codex → Claude: первое использование (macOS)

Коротко о том, как запустить цель на двух агентах и забрать результат. С Р12 агенты работают как в вашем терминале: ваши настройки, права и окружение, по умолчанию прямо в папке проекта. Подробности — `docs/ARCHITECTURE.ru.md` (раздел «Оркестрация агентов») и [ADR-20260924](../adr/ADR-20260924-orchestration-native-sessions.md). Ограничения — в конце.

## 0. Что нужно

- macOS. Linux допускается готовностью (supervisor использует группы процессов POSIX), но не проверялся; Windows не поддерживается.
- Codex и Claude, установленные и авторизованные так, как вы запускаете их в терминале. Приложение берёт ваши настройки, модель, режим прав, skills, plugins, MCP, hooks, инструкции проекта и память. Свои запреты оно не добавляет. Формат протокола сверен с `codex-cli 0.155.1` и Claude Code `2.1.280–2.1.281`. С другой версией готовность предупредит, но старт не запретит.
- Проект — корень git-репозитория: по нему строятся снимки и «Изменения». Submodules и неотслеживаемые вложенные репозитории не поддерживаются.
- Команды проверки, которыми вы сами проверяете проект: `php artisan test`, `composer test`, `npm test` и т. п. Зависимости (`composer install`, `npm install`) ставите вы или агент с вашего разрешения.

## 1. Открыть приложение

Режим Р12 (агенты в вашем окружении) есть только в текущей ветке разработки: `npm run dev` (или `npm run build`, затем `npm run preview`). Проверенная упакованная сборка Р10 (`/private/tmp/canvastty-r10-pkg-wrc5/…`) собрана до Р12: в ней ещё ограниченные режимы. Новая упакованная сборка не делалась.

Для первого знакомства лучше отдельный профиль: `--user-data-dir="$HOME/CanvasTTY-orchestration-profile"`.

## 2. Создать карточки

1. Правый клик по пустому месту холста → **«Агент Codex (лид)»**, укажите папку проекта (путь или «Выбрать…»), затем «Создать».
2. Ещё раз правый клик → **«Агент Claude (исполнитель)»** с **той же** папкой проекта.

## 3. Связать агентов

- Потяните мышью кружок-порт справа на карточке Codex и отпустите на карточке Claude. Появится линия и плашка связи.
- То же с клавиатуры: фокус на порт, Enter, затем «Связать сюда» на карточке Claude. Escape — отмена.
- Если связь недопустима (другой проект, та же карточка, повторная пара), причина появится на карточке лида.

## 4. Задать цель

На плашке связи — **«Новая цель»**:
- **Задача** и **критерии готовности** (по одному в строке).
- **Команды проверки** — по одной в строке. Приложение подставляет их по файлам проекта: Laravel → `php artisan test`, composer → `composer test` или `vendor/bin/phpunit`, Node → `npm test` или `node --test`. Проверьте и поправьте. Команды выполняет ваш login-shell в рабочей папке, как в терминале, без песочницы.
- **Где работают агенты:**
  - **«В папке проекта»** (по умолчанию) — агенты меняют ваши файлы напрямую. Незакоммиченные изменения сохраняются, ничего не откатывается само, ветку и индекс приложение не трогает;
  - **«В отдельной копии»** — клон в данных приложения. Ваши файлы не меняются, но игнорируемых файлов (`vendor/`, `node_modules/`, `.env`) в копии нет.
- **Лимиты** и **«Показать план перед выполнением»** — как раньше.
- **Готовность к запуску** — факты до любого хода модели:
  - версии CLI и окружение login-shell (PATH);
  - git: чистое ли дерево;
  - где работают агенты и стек проекта;
  - для Laravel — есть ли `vendor/`;
  - найдена ли программа каждой команды в PATH;
  - число тестовых файлов.

  Блокер отключает «Старт». Пункт «подтвердить» нужно отметить.
- **«Отличия от запуска в терминале»** — что всё-таки работает иначе (см. «Ограничения» ниже).

«Старт» — откроется панель запуска. Строка под заголовком говорит, где работают агенты: «Работает прямо в папке проекта — изменения сразу в ваших файлах: <путь>».

**Запросы разрешений.** Если ваши настройки CLI требуют подтверждения (команда, правка файла, сеть, MCP), запрос приходит в панель: «Агент просит разрешение». Кнопки:
- «Разрешить один раз»;
- «Разрешить на сессию»;
- «Отклонить».

Вопрос агента (AskUserQuestion, request_user_input) показан вариантами и полем «Свой ответ». Пока вы решаете, время хода не идёт. Приложение не отвечает за вас. «Стоп» снимает запрос и прерывает ход.

## 5. Остановить или продолжить

На панели видны только допустимые сейчас кнопки:
- **«Пауза после хода»** — дождаться конца текущего хода и встать на паузу. **«Не останавливаться»** — отменить паузу.
- **«Продолжить»** — продолжить после паузы. **«Один шаг»** — выполнить одну операцию и снова встать на паузу.
- **«Стоп»** — остановить сразу: текущий ход или проверка прерываются, дальше ничего не начинается. Остановленный run не продолжить; для новой попытки — «Новая цель».
- **Выход из приложения во время работы:** текущий ход останавливается, после запуска run стоит на паузе «по запросу пользователя». Сам он не продолжается — нажмите «Продолжить».
- **После сбоя приложения:** run показан на паузе с причиной и действиями восстановления («Принять результат хода», «Повторить ход», «Вернуть к последнему checkpoint» (после отметки подтверждения) или «Продолжить», если был прерван только прогон проверки).
- **«Результат команды неизвестен…»** (связь с приложением прерывалась) — нажмите «Повторить»: уйдёт тот же запрос, приложение вернёт уже записанный результат.

Панель закрывается крестиком. Снова открыть — «Открыть запуск» на плашке связи или на карточке.

## 6. Результат

- **В папке проекта:** изменения уже в ваших файлах. Агенты могли менять и файлы с вашими незакоммиченными правками: снимок на старте нужен для сравнения, он их не защищает. Вкладка «Изменения» показывает разницу с началом запуска (`git diff` от baseline). Если в цели отмечен «Создать коммит», Raoden Loom закоммитит только файлы запуска (с `CanvasTTY-Run: <id>` в сообщении), иначе закоммитьте сами, как обычно.
- **В отдельном worktree:** изменения в ветке `canvastty/<первые 8 символов id>`; путь и ветка — в «Итоге». Слейте или удалите её сами. Снимки хранятся в `control.git` приложения. В ваш репозиторий добавляются только ссылки `refs/canvastty/<runId>/…` (baseline и этапы) с их объектами; ветка, индекс и файлы не меняются. Сравнить с началом: `git diff refs/canvastty/<runId>/baseline`, новые файлы — `git status --short`. «Вернуть к checkpoint» в этом режиме нет.
- **В отдельной копии:** как раньше — ссылки `refs/canvastty/<runId>/stage-<n>` в исходном репозитории:

```sh
git for-each-ref refs/canvastty/                                              # найти полный id и этапы
git diff refs/canvastty/<runId>/baseline refs/canvastty/<runId>/stage-<n>     # что сделали агенты
git switch -c agents/<имя> refs/canvastty/<runId>/stage-<n>                   # посмотреть на новой ветке
```

## Автопилот и настройки проекта (Р13)

- **Как работать.** «Автопилот» сам готовит среду, планирует, исправляет и перепроверяет. «По шагам» показывает план и останавливается после каждого этапа. От прав это не зависит.
- **Настройки проекта** (кнопка в диалоге цели) задаются один раз:
  - где работают агенты;
  - команды проверки;
  - автоматическая подготовка;
  - права Claude и Codex (у каждого варианта показано, что именно передаётся CLI; «Полный доступ» — только явно).

  В «Дополнительно»:
  - шаги подготовки;
  - direnv;
  - push (remote и ветка);
  - QA (окружение, команда деплоя, команда проверки деплоя);
  - сохранённые разрешения;
  - «Проверить окружение».
- **После успешной проверки.** Коммит, push и QA выполняются, только если отмечены в цели и настроены в проекте. Каждое действие считается выполненным только после своей проверки: коммит в журнале, ветка на remote, команда проверки деплоя. Отчёт агента не считается.
- **Разрешения.** «До конца запуска» и «Всегда в этом проекте» повторно не спрашиваются для того же инструмента с теми же параметрами. Применение видно в ленте.

## Решения человека (журнал v2, пока только под признаком разработки)

В запусках журнала v2 (`CANVASTTY_JOURNAL_V2=1`, dev-сборка; для всех v2 включат после реальной серии) некоторые
решения принимаете только вы. Запуск их ждёт, автопилот за вас не решает. Карточка и связь пишут «Ждёт вашего
решения», в панели под «Дальше» — что решить.

- **Спорное замечание.** Проверяющий нашёл проблему в файлах уже закрытого замечания и не сказал, повтор ли это.
  Панель показывает рядом новое и закрытое.
  - «Новый дефект» — открывается новое блокирующее замечание.
  - «Повтор F<n>» — если файлы F<n> после закрытия не менялись, повтор отклоняется и ничего не блокирует; если
    менялись, F<n> открывается снова.

  После решения запуск продолжается сам.
- **Условие, которое подтверждаете вы.** «Выполнено» или «Не выполнено» — после ревью его этапа. «Не выполнено»
  возвращает этап исполнителю.
- **Лид предлагает снять условие или требование.** Панель показывает:
  - что снимается и почему;
  - что останется без покрытия;
  - для каждого открытого блокирующего замечания снимаемого условия — выбор: перенести на этап, закрыть, понизить.

  «Принять» — новый план. «Вернуть лиду» — прежний план остаётся, лид получает ваше пояснение.
- **Закрыть или понизить замечание.** Когда запуск стоит на паузе (шаг, лимит, ошибка отчёта), в «Итог → Замечания» у
  открытого замечания есть «Закрыть (ваше решение)» и «Понизить до пожелания».
- **Push и QA после запуска без проверок** — каждый шаг отдельно: «Отправить» / «Не отправлять», «Выполнить QA» /
  «Без QA». Решение действует только для дерева и commit, показанных в диалоге. Если файлы изменились, диалог
  покажет новое состояние, и решать придётся заново.

Итог не выглядит чище, чем есть. Снятое, пониженное и закрытое вами названо строкой «Решения человека вместо
доказательств». Снятые условия и требования стоят отдельно с причиной лида и никогда не считаются выполненными.
Пониженное замечание помечено «понижено человеком, не исправлено».

Если приложение закрылось во время решения: записанное решение сохраняется, незаписанное нужно принять снова. После
открытия запуск стоит на «восстановлен», «Продолжить» возвращает к тому же вопросу.

## Laravel: план первого запуска

1. Откройте «Новая цель» → «Настройки проекта». Шаги подготовки (`composer install`, `.env` и `key:generate`) подставлены по файлам. С включённой «Готовить среду автоматически» автопилот сам выполнит недостающие шаги до первого хода — в терминал идти не нужно.
2. Проверьте `.env` для тестов (`APP_KEY`, база для тестов — обычно sqlite в памяти из `phpunit.xml`). Работа в папке проекта использует ваш настоящий `.env`; в отдельной копии его нет.
3. «Новая цель»: команда проверки `php artisan test` (подставится сама), место — «В папке проекта». Если `php` не найден в PATH login-shell, готовность это скажет до старта: поправьте PATH в `~/.zprofile` или `~/.zshrc`, либо впишите полный путь.
4. Первый запуск — маленькая задача с одним этапом и «Показать план перед выполнением».

## Ограничения и отличия от терминала (Р12)

- **Интерактивные функции TUI** недоступны в управляемом ходе: слэш-команды, которые вы набираете сами, строка статуса, горячие клавиши. CLI работает в режиме протокола (Codex app-server, `claude -p` stream-json).
- **Окружение берётся из `$SHELL -ilc`** и из `.envrc` (direnv), если вы уже разрешили его в терминале. Переменные только от хуков приглашения (precmd) не попадут.
- **Codex app-server** в 0.155.1 помечен как экспериментальный.
- **Вопросы, формы MCP и выход из режима плана** проверены на поддельных CLI; на реальных — только после ограниченной серии (Р13).
- **Формы MCP-серверов** показываются в панели и проверяются перед отправкой; форму с неподдерживаемыми полями можно только отклонить. Ничего не заполняется за вас.
- **Снимки только в git-корне.** Для «Изменений» нужен корень git-репозитория.
- **Один запуск на папку.** Лид и исполнитель ходят по очереди.
- **Незакрытый запрос после перезапуска.** После перезапуска приложения ожидающий запрос разрешения пропадает вместе с процессом CLI, а ход восстанавливается как прерванный.
- **CLI сами сохраняют свои сессии** (`~/.claude/projects/`, `~/.codex/sessions/`) — так же, как в терминале.
- **Реальный прогон моделей в режиме Р12 не выполнялся:** проверено на поддельных CLI, говорящих теми же протоколами.

## Ограничения MVP (запуски, созданные до Р12)

- **Только macOS.** На Linux run не завершится: проверки встают на `sandbox_unavailable`. Windows не поддерживается.
- **Claude работает в кандидатном режиме `structured-edit`:** Read/Edit/Write/Glob/Grep, без shell, $1 на ход. Ограничения правок — политика CLI, а не граница ОС.
- **При старте не ищутся процессы**, оставшиеся после убийства всей группы процессов приложения.
- **Результат забирается только через Git.** Интерфейс не показывает имена checkpoint-ссылок и ничего не сливает.
- **CLI сами сохраняют свои сессии** в домашнем каталоге: `~/.claude/projects/`, `~/.codex/sessions/`.
- **Панель показывает только последний run связи.** Одна связь — не больше одного активного run.
- **У Codex нет денежного лимита.** Расход ограничивают лимиты ходов и времени.
