# Политика безопасности

[English](SECURITY.md) · [Русский](SECURITY.ru.md)

## Поддерживаемая версия

Raoden Loom `1.0.2` — текущий релиз и единственная ветка, получающая исправления. Кроссплатформенные пакеты не подписаны, поэтому операционная система может потребовать отдельно подтвердить запуск.

## Сообщение об уязвимости

Не публикуйте учётные данные, историю терминала, приватные пути и подробности эксплуатации в открытом issue.

Используйте **Security → Report a vulnerability** в репозитории, если доступна приватная отправка отчётов. Если она недоступна, создайте публичный issue только с короткой нечувствительной просьбой предоставить приватный канал связи.

Укажите версию Raoden Loom, операционную систему, затронутый сценарий, влияние и минимальные шаги воспроизведения. Замените настоящие токены, имена пользователей, домашние каталоги, названия проектов, промпты и вывод терминала синтетическими значениями.

## Граница данных

- Учётные данные провайдеров остаются в локальном хранилище соответствующего CLI. Raoden Loom читает их только в доверенном main-процессе и не копирует в файлы проекта или настройки.
- Настройки Raoden Loom хранятся в пользовательском каталоге Electron `userData`.
- Ограниченный scrollback PTY находится в памяти процесса и не записывается в репозиторий.
- У Raoden Loom нет собственного telemetry endpoint; приложение не выгружает свои логи.
- Запросы usage отправляются только через адаптер соответствующего провайдера. Через IPC проходят очищенные снапшоты лимитов, но не сырые ответы или credentials.
- Runtime-плагины — статические GitHub-пакеты в `userData/plugins`. Raoden Loom не запускает их repository scripts и не предоставляет Node.js. UI плагина работает в sandboxed frame/окне и получает только подтверждённые при установке разрешения. Это всё равно сторонний код: перед установкой проверьте исходники и разрешения `network`/`external:open`/`browser:open`.
- Хранилище плагина изолировано по его ID в `userData/plugin-storage`, ограничено 64 КБ и удаляется при uninstall. Доступ к сессиям не включает PTY buffers и рабочие каталоги.
- Разрешения плагинов на медиапапки находятся в `userData/plugin-media-libraries.json`, содержат выбранные абсолютные пути и удаляются вместе с плагином. Плагин с разрешением на запись плейлистов может создавать ограниченные по размеру файлы в каталоге `Playlists/` выбранной библиотеки.
- Встроенный браузер доступен из HOME в `1.0.2` и использует постоянный Electron-раздел `canvastty-browser` для cookies, cache и site storage. Remote pages работают в sandbox без Node.js и preload Raoden Loom; навигация ограничена HTTP(S), а cookies, пароли, authorization headers, local storage, произвольный JavaScript и raw CDP агентам не открываются. Browser data остаются локально в Electron `userData`, если только посещённый сайт сам не передаст их в сеть.
- Browser-команды записываются в очищенный локальный hash-chain audit в `userData/browser/audit`. Активный файл ротируется при 100 МБ; ротированные файлы старше 30 дней удаляются при инициализации или ротации. Typed/page text, screenshots, credentials, query/fragment URL, headers, cookies и tokens не сохраняются. Очистка browser data намеренно оставляет audit evidence.

Репозиторий запускает `npm run audit:secrets` в CI и перед упаковкой. Это защитный барьер, а не разрешение временно коммитить секреты: если настоящий секрет попал в Git history, немедленно отзовите его и перепишите/очистите затронутую историю до публикации.
