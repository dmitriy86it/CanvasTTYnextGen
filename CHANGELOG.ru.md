## Не выпущено

- «Рабочая папка»: команды только для чтения больше не останавливают запуск запросами разрешений. В запуске 7303d772 Claude спрашивал про каждую команду только для чтения вида `cd … && bash -c '…'`, с переменной (`$f`, `$O`) или со скобкой с кавычкой. Это были не просьбы выйти из песочницы, а собственная проверка Claude, которая не смогла разобрать строку команды заранее. В песочнице приложение теперь отвечает на такой запрос само: команда по-прежнему выполняется в песочнице Claude, которая пишет только в рабочую папку и не ходит во внешнюю сеть. Просьба выйти из песочницы, сетевой запрос песочницы, запись вне папки, правило «спрашивать» пользователя и проверка безопасности по-прежнему идут к человеку. Проверено на реальном Claude 2.1.294: команды из 7303d772 прошли без запросов, запись в домашнюю папку не прошла («operation not permitted»), curl во внешнюю сеть остановлен до решения человека.
- Запрос разрешения на команду только для чтения, если таких в запуске было больше 3, предлагает «Разрешить команды только для чтения до конца запуска» (просмотр и поиск по файлам — cat, head, sed -n, grep, find без -exec, ls, wc…; без сети, без записи и без git). Действует только на этот запуск и хранится в памяти: после перезапуска приложения спросит снова.
- Размер карточек агентов меняется так же, как у карточек терминала: те же ручки, выделение, групповое перетаскивание и масштаб. Самый маленький размер — прежняя карточка, самый большой — как у терминала. Размер хранится на холсте (не в журнале запуска) и восстанавливается после перезапуска. «Развернуть / Свернуть» в шапке карточки (или двойной клик по шапке) переключает между компактным размером и размером, который был в последний раз, когда карточка была больше.
- В увеличенной карточке видны последние события её агента — инструменты, команды, сообщения, как в ленте активности; новые внизу. Лента сама прокручивается к новым событиям; если прокрутить вверх, она остаётся на месте, пока вы не вернётесь вниз. Домашняя папка показана как `~`.
- Строки карточки больше не обрезаются по высоте: каждая строка — одна строка, длинная заканчивается «…», полный текст в подсказке. Проект — одной строкой, время последнего события — рядом с состоянием.
- Ждущий агент больше не повторяет дословно строку работающего: «Ждёт: Claude выполняет этап 1: …», одной строкой.

## 1.5.12 — 2026-10-08

Проверка до старта, стоимость запуска, пауза лимита, «Забрать результат», отдельная копия по умолчанию.


- «Забрать результат» для запуска в отдельной копии или worktree (UX-аудит 2026-10-05, топ-10 №10) — главная кнопка такого завершённого запуска; она же есть у остановленного и у запуска на паузе с изменениями. Источник — последняя контрольная точка запуска; если её нет — текущее состояние рабочей копии, с явной пометкой. «Создать ветку в проекте» (безопасный путь): ветка `raoden/<цель>-<id>` (имя видно и меняется) с изменениями запуска поверх того, с чего запуск начался; рабочая папка, индекс и текущая ветка не трогаются, занятое имя не перезаписывается (предлагается другое). В worktree результат коммитится в ветку запуска, и она переименовывается. «Применить к рабочей папке» — только если изменения ложатся на ваши файлы как есть, это проверяется заранее; при пересечении с вашими незакоммиченными правками ничего не пишется и файлы называются. «Показать изменения» открывает вкладку «Изменения». Потом в итоге: «Результат забран: ветка …» или «применён к рабочей папке в …»; повторное нажатие ничего не делает дважды. Всё делает git приложения, не агент; сведения — в файле рабочей области запуска, не в журнале.
- «Отдельная копия» — место работы нового проекта по умолчанию; сохранённые настройки проектов не меняются. В настройках проекта — все три места. В режиме «В папке проекта» с незакоммиченными изменениями диалог цели говорит, сколько их, и предлагает «Переключить на отдельную копию» — только для этой цели.
- Если «Проверить сейчас» нашла команды, падающие ещё до изменений, «Старт» спрашивает: «Убрать падающие команды из этого запуска» (основная), «Запустить как есть — агенты будут чинить и их» или вернуться к цели. Настройки проекта не меняются.
- Формулировки: команда проверки «прошла / упала до изменений агентов (во временной копии проекта)»; расход на карточке — «Вызовы этого агента», на табло — «Всего по запуску».

- «Проверить сейчас» в диалоге цели и в настройках проекта (UX-аудит 2026-10-05, топ-10 №8): проверка до старта без вызова моделей. Каждый пункт — «ок», предупреждение или блокер, с одной фразой «что сделать» и, где можно, кнопкой «Исправить», которая открывает нужную настройку или команды проверки. Пункты: CLI и их режимы прав (пробы возможностей из 1.5.11); вход в аккаунт — только если справка самого CLI предлагает команду статуса (`codex login status`, `claude auth status`); модели ролей (Codex — по списку моделей; модель Claude до старта не проверяется); самотест песочницы проверок и git в ней; подготовка и команды проверки на исходном коде — во временной копии или worktree, созданных так же, как для запуска, с теми же правилами клонирования зависимостей, в пределах 10 минут. По каждой команде: «прошла», «упала» (первые строки вывода) или «не уложилась во время»; если команды падают ещё до изменений — «Проверки уже падают до изменений — агенты будут считать их обязательными». В режиме «В папке проекта» команды до старта не запускаются. Временная копия удаляется, в том числе при ошибке. Строка итога говорит, сколько блокеров и предупреждений; старт блокируют только блокеры. Облегчённая проверка (без подготовки и команд) по-прежнему идёт сама при открытии диалога цели.
- Табло запуска и карточки агентов показывают, во что обходится запуск (Н9): вызовы моделей по ролям, токены, о которых сообщил CLI (их сообщают и Codex, и Claude; без долларов), время работы относительно лимита времени, израсходованные ходы из лимита и время до дедлайна.
- Пауза лимита (Н7) показывает текущее значение каждого лимита и сколько израсходовано, отмечает достигнутый, предлагает новое значение с единицами и одну главную кнопку «Поднять лимит и продолжить» — запуск идёт дальше без отдельного «Продолжить».
- Если Claude не ответил на пробу возможностей за 30 с (медленные хуки при старте), в фоне идёт одна повторная проба на 90 с. Если не ответил и на неё — «Рабочая папка» становится предупреждением, а не блокером: «Режим «Рабочая папка» для Claude не подтверждён пробой… Запуск безопасен: при недоступной песочнице Claude сам откажется работать». «Старт» доступен; таймаут не сохраняется между запусками приложения.
- Настройки → «Уведомления»: если число не появляется на иконке в Dock, настройки подсказывают включить «Значки на иконке приложения» в Системных настройках → Уведомления → Raoden Loom.
- Smoke `workspaces-ui` и `workspaces-background` снова проходят: их подставной лид отвечал в формах журнала v1, после того как v2 стал форматом по умолчанию.

## 1.5.11 — 2026-10-08

Обновлённые CLI больше не блокируют запуск: проба возможностей вместо списков версий.


- Обновлённые CLI больше не блокируют запуск. Возможности установленных Codex и Claude теперь проверяются пробой без модельного вызова, а не по списку версий: у Claude — `--help` и сессия с переключателями «Рабочей папки»; у Codex — схема протокола app-server (поток не создаётся, `~/.codex/config.toml` не меняется). Результат хранится по программе, версии и времени изменения; новая версия проверяется заново сама. Codex 0.160.0 и Claude 2.1.293 работают во всех режимах прав, предупреждения «протокол не сверялся» больше нет. Предупреждение появляется, только если изменилось то, на что опирается запуск, и называет, что именно.
- Готовность и старт решают по одному правилу: режим прав или модель, которых CLI не предлагает, — блокер готовности с именем CLI, версией и тем, чего нет, например «Claude 2.1.293: не принимает настройки песочницы (--settings) — режим «Рабочая папка» недоступен». «Старт» неактивен, причина рядом; старт не отказывает по причине, которой не было в готовности.
- У такого блокера есть кнопка «Запустить <CLI> в режиме «Как в моём терминале» только для этого запуска»: после подтверждения, объясняющего более широкие права, CLI работает с вашими собственными настройками. Настройки проекта не меняются; права молча не понижаются и не расширяются.

## 1.5.10 — 2026-10-07

Улучшения интерфейса по UX-аудиту 2026-10-05: понятные паузы, итог без противоречий, решения и диалоги, уведомления и значок в Dock.


- Паузы говорят, что случилось, почему и что делать (UX-аудит 2026-10-05). У каждой из 27 причин паузы свой заголовок, одна фраза «почему», конкретный следующий шаг и одна главная кнопка — действие, которое запуск на этой паузе действительно примет. Заголовок больше не повторяется строкой ниже, а шесть разных пауз больше не называются одинаково «Нужно ваше решение». Недоступная песочница проверок на macOS больше не советует «запустите на macOS»: сказано, что самопроверка песочницы не прошла и что команды проверки можно вписать в цель; что песочницы нет, говорится только на платформе без неё.
- Главная кнопка панели запуска — действие самой паузы («Продолжить», «Повторить ход», «Ответить на вопрос», «Увеличить лимит»…); «Стоп» второстепенный, контурный и последний — главный только там, где пауза ничего, кроме остановки, не допускает. Пока запуск работает, главная кнопка — «Пауза».
- Ярлык связи, карточки агентов, лента и виджет активности пишут «Ждёт вас: …» для паузы, где нужно ваше действие, и «Пауза: …» для той, которую достаточно продолжить, — теми же словами, что панель.
- Предложение лида убрать критерии готовности первым и главным предлагает «Вернуть лиду»; «Принять снятие» — второстепенная кнопка с предупреждением, что убранные критерии перестанут проверяться. У блокирующего замечания «Понизить до пожелания» и «Закрыть» сопровождает подсказка, что безопасно — ничего не нажимать.
- Блок «Итог» больше не спорит с заголовком и сам с собой (UX-аудит 2026-10-05, Н5). У завершённого запуска «Цель принята финальным ревью: да»; у идущего — «ещё нет», а не «нет». Без команд проверки критерий, отмеченный ревью, пишется «отмечено ревью, командами не проверено», а не «выполнено», а проверки — «не запускались». На паузе «лид изменил файлы» изменения — «неизвестно», а не «нет». Пауза никогда не пишет «От вас: ничего не нужно». Следующий шаг после работы в папке проекта — «если изменения есть, закоммитьте их».
- Коды журнала читаются словами: «Замечание 1», «Критерий 2», «Требование 2» вместо F1, C2, R2; сам код — во всплывающей подсказке. «Условия» в панели везде называются «критериями».
- Агентов просят писать то, что читает человек, — заголовки и задачи плана, вопросы, замечания, пояснения — на языке интерфейса в момент создания цели; коды, пути и команды не переводятся. Старые цели не меняются.
- В диалоге цели и в настройках проекта «Старт» / «Сохранить» закреплены внизу и видны без прокрутки; радиокнопки и галочки рисуются в светлой схеме диалога (раньше выглядели инвертированными). Флаги CLI за каждым режимом прав — под «Подробнее».
- В предложении лида убрать критерии заголовок и список снимаемого остаются на виду, пока вы прокручиваете к кнопкам; «Вернуть лиду» и «Принять снятие» — в одной строке.
- Push и деплой на QA — две отдельные группы, «Отправка изменений (push)» и «Выкладка на тестовый сервер (деплой на QA)», у каждой «подтвердить» или «отклонить», с пояснением, что решения независимы.
- Ярлык связи на холсте больше не перекрывает карточку Codex: он стоит между связанными карточками, если там есть место, иначе под ними (или над).
- Команды проверки, которые ещё не запускались, пишутся «ещё не запускались», а не «0 из N прошли». «Откуда команды» говорит «лид не предложил ни одной», если их нет. Спорное замечание объясняет, к чему ведёт каждый выбор. «Старт» и «Сохранить» — тёмные на светлом диалоге, и рядом сказано, почему кнопка неактивна. Диалог цели спрашивает «Требования к результату».
- Без команд проверки итог говорит прямо — вы их не задали, лид не предложил, результат проверен только ревью, — а раздел критериев объясняет, что требование выполнено, когда выполнены его критерии. Диалог цели больше не показывает пример команды в пустом поле и «подставлены по файлам проекта», когда ничего не подставлено. Настройки прячут команды подготовки под «Подробнее».
- Подсказки: «Один шаг» и «Продолжить» при наведении объясняют разницу. Словарь объясняет одной фразой при наведении лид, исполнитель, проверяющий, ход, раунд, песочница, push, QA, критерий и замечание (пунктирное подчёркивание), на русском и английском.

- Уведомления macOS о запусках агентов (UX-аудит 2026-10-05, пункт 3): запуск ждёт вас (паузы, которые ярлык называет «Ждёт вас», и запрос разрешения), запуск завершён (с проверками или «Завершено без проверок» — другой текст) и запуск остановлен ошибкой. Только когда окно не в фокусе или свёрнуто; текст — название проекта и короткая причина, без путей, команд и содержимого файлов. Одно уведомление на изменение состояния; последнее уведомлённое состояние каждого запуска хранится вне журнала, поэтому после перезапуска ничего не повторяется. Клик выводит окно вперёд, переключает на пространство запуска, ведёт камеру к его связи и открывает панель.
- Значок в Dock показывает, сколько запусков ждут вас во всех пространствах (при 0 скрыт); по желанию иконка один раз подпрыгивает, когда запуск начинает ждать.
- Настройки → «Уведомления»: «Ждёт вас», «Завершён», «Ошибка», «Значок в Dock» (вкл) и «Подпрыгивание иконки при ожидании» (выкл). Если macOS уведомления не показывает (нет разрешения, неподписанная сборка), настройки объясняют, как разрешить их в Системных настройках, а окно показывает баннер.
- Диалог цели: требование, похожее на команду проверки (`npm …`, `node …`, `pytest`, `./…`, `--test` …), получает подсказку «Похоже на команду проверки. Перенести в „Команды проверки"?» с кнопкой «Перенести»; само ничего не переносится.
- У завершённого запуска, следующий шаг которого — вкладка «Изменения», главная кнопка «Посмотреть изменения»; «Новая цель» — второстепенная.
- «Эти карточки уже связаны» на карточке — информация, а не ошибка: больше не красная.
- Словарь объясняет контрольную точку, worktree, «подтверждено журналом», «со слов агента» и служебную ветку `canvastty/…`.
- Smoke: проверка герметичности судит процесс по программе, которую он запускал в момент снятия дерева процессов, — короткий процесс приложения, чей PID занял посторонний (параллельный `npm test`), больше не считается чужим.
## 1.5.9 — 2026-10-05

- Копирование из терминалов сохраняет кириллицу и псевдографику: «Этап 0», скопированный из Claude Code или Codex в карточке терминала, больше не превращается в «–≠—В–∞–њ 0». У приложения, запущенного из Finder или Dock, не было локали, и CLI, которые карточка запускает напрямую (не через login shell), копировали через `pbcopy` как Mac Roman. Теперь при старте приложение задаёт `LANG` — локаль системы в UTF-8 (`ru_RU.UTF-8`, иначе `en_US.UTF-8`; на Linux `C.UTF-8`), если не задан ни `LC_ALL`, ни `LC_CTYPE`, ни `LANG`; это наследуют терминалы, CLI агентов, подготовка и проверки. Ваши значения сохраняются, не-UTF-8 — предупреждение в логе. ⌥ + мышь выделяет средствами терминала поверх CLI, который перехватывает мышь.

## 1.5.8 — 2026-10-04

- **Журнал v2 включён по умолчанию** (этап A завершён). Новые запуски пишутся в v2 без флага разработки: лид планирует с требованиями и условиями, ревью делает отдельный проверяющий, команды проверки можно оставить пустыми — их предложит лид, запуск без проверок заканчивается как «Завершено без проверок», а push и QA делает только после вашего подтверждения. Всё, что ниже помечено «только под флагом разработки», вошло в этот выпуск. Запуски, начатые в v1, продолжаются в v1; журнал dev-сборок A1–A3 показывается только для чтения. Шлюзом была реальная серия на настоящих CLI: R1–R5 прошли (`docs/agent-orchestration/evidence/real-a-gate/attempt-5`).
- Модель для каждой роли: в настройках проекта и поверх них в цели лиду, исполнителю и проверяющему задаётся модель или «Как в CLI» (по умолчанию: модель не передаётся, решает конфиг CLI). Для Codex — то, что `model/list` говорит о вашем аккаунте (без хода модели, хранится на сессию приложения, «Обновить» спрашивает снова); для Claude — opus, sonnet, haiku и любое другое имя. Модель передаётся только этому потоку Codex или запуску Claude: `config.toml` и настройки Claude не меняются. Модель Codex, недоступная вашему аккаунту, останавливает старт до первого вызова модели и говорит, где её сменить. Панель запуска и карточки участников показывают модель, которую сообщил CLI.
- Команды проверки, предложенные лидом и запущенные в песочнице проверок, могут вызывать git: git больше не пытается читать `~/.gitconfig`, который песочница запрещает, и не падает с кодом 128 на любой команде.
- Пока проверяющий смотрит этап, закончивший ход исполнитель пишет, что ждёт ревью.
- Планы журнала v2: лиду сказано, что условие «изменение» доказывается только изменёнными файлами, поэтому «файл не меняется» — это команда проверки или вовсе не условие. На такое условие проверяющий отвечает «не выполнено» с запросом нового плана, а не «выполнено» без файлов, и новый план узнаёт, какие условия не выполнены и почему. Раньше запуск мог встать на таком условии: «выполнено» без файлов отклонялось, «не выполнено» держало этап до исчерпания раундов.
- Ревью журнала v2: ревью предлагаются только условия и требования, которые оно решает (ревью этапа — условия «изменение» этого этапа; таких нет — отметок нет вовсе), а условия «команда проверки» названы в задании отдельно: их засчитывает только команда. Лишняя отметка ревью — условия «команда» или «человек», требования, снятого человеком, неизменённого файла рядом с изменёнными — больше не отклоняет весь отчёт: она отбрасывается, никогда не засчитывается, а лента говорит об этом («проверяющий отметил C3 — не учтено: условие засчитывается командой»).
- Codex больше не дописывает в ваш `~/.codex/config.toml` запись доверия `[projects."…"]` для отдельной копии или worktree каждого запуска: папке запуска доверие даётся только на её поток. В папке проекта ничего не меняется. Ход Codex, отклонённый из‑за модели, которую ваш аккаунт не поддерживает, теперь ставит паузу с этой причиной и подсказкой, где сменить модель, а не «ошибкой окружения».
- Права агентов: новый проект начинает в режиме **«Рабочая папка»**. Агенты пишут только в рабочую папку запуска; всё остальное — через запрос разрешения, который ставит запуск на паузу до вашего ответа, в автопилоте тоже. Claude работает с `acceptEdits` и своей песочницей (команды без вопросов, без внешней сети, localhost разрешён), Codex — с `workspace-write` и `on-request`. **«Как в моём терминале»** теперь настройка проекта и включается с подтверждением предупреждения; сохранённые настройки и начатые запуски свой режим не меняют. Табло запуска и карточки участников показывают режим, «Как в моём терминале» — предупреждающим цветом. Пока предложение плана ждёт вашего решения на другой паузе, «Уточнить» и «Поднять лимит» показаны выключенными с подсказкой.
- Журнал v2 (этап A, A4, только признак разработки; v2 по умолчанию по-прежнему выключен): решения человека и финал. Некоторые решения принимает только человек в панели запуска, и запуск их ждёт; автопилот их не принимает:
  - спорное замечание показано рядом с закрытым, повтором которого оно может быть: «Новый дефект» или «Повтор F<n>»;
  - условие, которое подтверждает человек: «Выполнено» или «Не выполнено»;
  - план, снимающий условия или требования, — предложение: «Принять» с выбором для каждого открытого блокирующего замечания снимаемого условия или «Вернуть лиду»;
  - на паузе открытое замечание можно закрыть, а блокирующее — понизить до пожелания.

  Каждое решение записывается с деревом и состоянием, которое видел человек; устаревшее отклоняется, и панель показывает текущее состояние. Условие «изменение», чьи файлы менялись после приёмки этапа, засчитывается только после подтверждения финальным ревью; отказ финала возвращает такие условия следующему плану. Итог не выглядит чище, чем есть: снятые требования и условия, пониженные и закрытые человеком замечания названы «Решения человека вместо доказательств», а не выполненными или исправленными. Оборванный хвост журнала v2 срезается при открытии (байты сохраняются отдельно), а решение, записанное до сбоя, после него стоит. Включение v2 для всех — один переключатель, выключенный до реальной серии.
- Журнал v2 (этап A, A3, только признак разработки): замечания ревью и проверяющий. Этапы и итог проверяет отдельный проверяющий — Codex в новой сессии на каждое ревью, без отчёта исполнителя, — а лид только планирует. Проверяющий сообщает замечания, блокирующие или пожелания; номера F1, F2, … даёт приложение и не меняет. Блокирующее замечание держит свой этап и запуск, пока следующее ревью не закроет его на изменённом дереве, назвав файлы, изменённые для него. Результат каждого ревью и то, что сделало с ним приложение, записываются в журнал вместе с историей каждого замечания; журнал с «Завершено» при открытом блокирующем замечании показывается повреждённым. В итоге — раздел «Замечания» с номером, уровнем, статусом и историей каждого; карточки и лента активности пишут «Открыто блокирующих: N»; панель запуска показывает проверяющего участником.
- Журнал v2 (этап A, A2, только признак разработки): требования и условия готовности. Каждый критерий приёмки цели — требование R1, R2, …; каждый этап плана лида перечисляет условия, которые их доказывают; номера C1, C2, … даёт приложение и не меняет, новый план сохраняет открытые. Условие выполнено, если команда проверки прошла на дереве, на котором запуск завершается (успех на старом дереве не засчитывается), или если ревью лида назвало файлы, изменённые запуском. Этап принимается только с выполненными условиями, запуск завершается только при выполненных условиях и требованиях, а журнал с «Завершено» без этих доказательств показывается повреждённым. В итоге — раздел «Условия»: требования, их условия, статус и доказательство; карточки и лента активности пишут «N из M условий выполнено».
- Журнал v2 (этап A, A1.1, только признак разработки): команды проверки, предложенные лидом, идут в своём профиле Seatbelt — сеть только этой машины, запись в рабочую папку запуска и временный каталог — после самотеста профиля, поэтому автопилот принимает их сам. Проверка, которую остановила песочница, ставит паузу «Проверке нужно больше прав»: команду лида как есть без песочницы не запустить — человек открывает её полностью и сохраняет как свою, и тогда она идёт в его shell. Если лид не нашёл команд, автопилот идёт без проверок (пошагово: «Добавить команды» или «Продолжить без проверок»). Журнал v2 окончательной формы — только просмотр, записи как есть. Команды, введённые человеком, — как прежде.
- Журнал запуска v2 (этап A, A1), только под признаком разработки `CANVASTTY_JOURNAL_V2=1` (упакованная сборка его игнорирует; пользовательские запуски по-прежнему пишутся в v1): команды проверки цели можно оставить пустыми — тогда лид предлагает их с обоснованием каждой (или объясняет, почему их нет), а человек принимает или изменяет их до начала работы; автопилот тоже ждёт, потому что нативные проверки идут без песочницы. Запуск без проверок заканчивается статусом «Завершён без проверок» в панели, на карточках, чипе связи, в виджете активности и истории пространства, нигде не «Завершён»; commit делается, push и QA ждут решения человека для показанных дерева и commit. Журнал v2 сборка 1.5.7 показывает только для чтения; журналы v1 и их запись не изменились.
